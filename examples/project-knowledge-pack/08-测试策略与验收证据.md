# Agent Studio Desktop：测试策略与验收证据

## 自动化测试

后端当前有 17 个测试，最终执行结果是 17 个通过、0 失败、0 错误。

`AgentStudioApplicationTests` 验证 Spring 上下文能加载。`SystemStatusControllerTests` 验证健康状态接口。`AgentBuilderIntegrationTests` 验证模型配置、草稿发布和不可变版本：发布 v1 后修改模型与草稿，再发布 v2，必须保证 v1 快照不变。

`ChatStreamIntegrationTests` 使用可控模型网关验证普通 SSE、成功工具循环、RunStep 查询、重复工具请求上限和高风险拒绝链路。`AgentBuilderIntegrationTests` 证明发布后的工具快照不会随草稿修改。`ToolRegistryTests` 验证慢工具按独立超时停止。`ApprovalServiceTests` 验证批准只能用原 SHA-256 一次性消费，`WriteWorkspaceNoteToolTests` 验证受控目录写入和路径穿越拒绝。`TextChunkerTests` 验证重叠切块，embedding 测试验证 LocalHash 和 Ollama 请求、维度及前缀隔离。

`OllamaEmbeddingGatewayTests` 启动本地 HTTP 假服务，验证文档批量请求、查询指令只作用于 query、dimensions 参数和返回维度。`RagRetrievalEvaluationTest` 对 00–10 文档运行冻结的 30 道题，输出 Recall@5、MRR、无答案误召回率、阈值扫描和延迟。

`RunControlIntegrationTests` 让 mock 模型阻塞五秒：主动取消必须中断调用、发送 CANCELLED，并可在历史与 RUN_TERMINATION 中查询；另一用例把总时限压到 300 毫秒，验证自动进入 TIMED_OUT。这样测试的是正在阻塞的真实控制路径，而不只是直接调用状态更新方法。

测试环境使用内存 H2 代替 MySQL，并关闭向量数据源，因此启动快、结果稳定。真实 MySQL 和 pgvector 行为通过独立验收补足，不能只依赖 H2。

DeepSeek 真实调用验证了 OpenAI 兼容请求和中文 SSE 增量，最终收到 done。RAG 真实验证包括创建知识库、上传 Markdown、状态 READY、发布绑定知识库的 AgentVersion、sources 返回、删除后三处数据消失、重新上传恢复。

语义升级又验证了真实 Ollama、pgvector v2 和重建 API：数据库中向量确认为 1024 维、模型为 qwen3、版本为 qwen3-0.6b-v1；改写问题命中正确来源。知识包扩充后，LocalHash 与 Qwen 在同一语料上重新生成带语料哈希的结果，Qwen 的 Recall@5、整体 MRR 和改写题 MRR均优于 LocalHash；最终数字见评测报告与 11 号文档。

## 为什么自动化和真实验收都要有

自动化测试适合保证版本隔离、协议结构和算法不回归，但无法证明 Docker 端口、真实数据库方言、环境变量继承和外部模型兼容。真实验收能覆盖这些问题，却不适合每次提交都执行。因此项目把两类证据分开记录。
