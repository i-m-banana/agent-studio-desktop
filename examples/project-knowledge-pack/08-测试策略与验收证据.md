# Agent Studio Desktop：测试策略与验收证据

## 自动化测试

后端当前有 6 个测试，最终执行结果是 6 个通过、0 失败、0 错误。

`AgentStudioApplicationTests` 验证 Spring 上下文能加载。`SystemStatusControllerTests` 验证健康状态接口。`AgentBuilderIntegrationTests` 验证模型配置、草稿发布和不可变版本：发布 v1 后修改模型与草稿，再发布 v2，必须保证 v1 快照不变。

`ChatStreamIntegrationTests` 使用可控的模型网关和知识来源验证 SSE 事件，包括 run、sources、delta 和 done。`TextChunkerTests` 验证长文本会产生多个有重叠的 chunk，且不超过最大范围。`LocalHashEmbeddingTests` 验证 384 维向量、归一化和相似文本比无关文本更接近。

测试环境使用内存 H2 代替 MySQL，并关闭向量数据源，因此启动快、结果稳定。真实 MySQL 和 pgvector 行为通过独立验收补足，不能只依赖 H2。

## 前端验证

前端运行 `npm run build`，该命令先执行 TypeScript project build，再执行 Vite 生产构建。最终构建成功。浏览器冒烟检查确认四个导航入口、知识库创建表单、上传控件、Agent Builder 和对话测试台正常渲染。

## 真实环境验证

Docker Desktop 中 MySQL 映射为 23306，pgvector 映射为 15432，用户确认二者都是 healthy。Spring Boot 真实连接 MySQL 8.4，Flyway V1 和 V2 成功。向量连接池连接 PostgreSQL，自动创建 vector extension、knowledge_chunk 和 HNSW 索引。

DeepSeek 真实调用验证了 OpenAI 兼容请求和中文 SSE 增量，最终收到 done。RAG 真实验证包括创建知识库、上传 Markdown、状态 READY、发布绑定知识库的 AgentVersion、sources 返回、删除后三处数据消失、重新上传恢复。

## 为什么自动化和真实验收都要有

自动化测试适合保证版本隔离、协议结构和算法不回归，但无法证明 Docker 端口、真实数据库方言、环境变量继承和外部模型兼容。真实验收能覆盖这些问题，却不适合每次提交都执行。因此项目把两类证据分开记录。
