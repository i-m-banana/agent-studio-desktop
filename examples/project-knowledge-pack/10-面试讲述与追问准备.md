# Agent Studio Desktop：面试讲述与追问准备

## 90 秒项目介绍

我主导做了一个单机优先的智能体搭建工具 Agent Studio Desktop，目标是让用户不改 Java 代码，就能配置 OpenAI 兼容模型、提示词和知识库，发布固定版本的 Agent，并在网页上做流式问答和查看引用来源。后端采用 Java 21 和 Spring Boot 模块化单体，前端是 React + TypeScript，MySQL 保存业务配置，PostgreSQL + pgvector 保存向量，本地文件系统保存原始文档。

我没有直接扩展旧平台，而是先收敛复杂度：放弃多模块 DDD 和动态 Bean，使用可编辑 AgentDefinition 加不可变 AgentVersion，保证历史会话不受后续配置修改影响。开发上先跑通模型配置、发布和 SSE，再加入 Tika 解析、重叠切块、向量检索和 sources 事件。真实环境中解决了 Windows 数据库端口冲突、双数据源自动装配连错库等问题，并用 DeepSeek、MySQL 和 pgvector 完成端到端验收。

RAG 最初使用 384 维词法哈希跑通闭环，随后建立 30 道冻结题集，用指标证明 Qwen 对改写问题有效，再通过 EmbeddingGateway 和独立 1024 维索引投入生产。最终同语料对比中，Qwen 保持全部可回答题 Recall@5 命中，整体与改写题 MRR 均优于 LocalHash，本机延迟也在预算内。统一查询指令曾在扩充前语料上让 MRR 从 0.8160 降到 0.6917，因此通过消融取消默认前缀。具体最终数值放在不参与盲测语料的 11 号文档和评测报告中。

在此基础上，我实现了显式工具运行时。模型只提出 tool call，平台校验版本快照，再由 SafeExecutionGateway 统一完成 Schema 校验、风险审批、限时执行和 AuditEvent，并把 Observation 送回模型。先用 current_time 验证低风险链路，再用受控写入验证参数绑定审批，真实完成拒绝不写和批准写入。随后补上运行治理：runId 绑定执行线程和截止时间，用户取消与总超时可中断阻塞调用，最终写入 RUN_TERMINATION；独立页面能回看完整步骤和安全审计，重启会关闭遗留状态。SSH、Coding、身份和真正断点续跑仍如实保留为后续。

随后我把 MCP 做成动态能力入口。平台能配置 Streamable HTTP 和本机 stdio Server，按标准生命周期发现 Tools、Resources 和 Prompts。工具进入原 ToolRegistry，并通过 Server 命名空间和描述指纹避免重名与历史漂移；Resource 可预览或复用既有 RAG 入库链；Prompt 由用户填参后主动获取，不会暗改 Agent。MCP 工具默认 HIGH，仍走参数审批、目标绑定、超时、取消和审计。stdio 不经 shell，按次启动并分级回收进程树；Server 还支持同步历史、无秘密配置导入导出和保留历史引用的安全删除。HTTP 与 stdio 自动化都覆盖三类核心原语。

## STAR 故事：双数据源问题

情境：加入 pgvector 后，应用同时有 MySQL 和 PostgreSQL 两个数据源。任务：让 Flyway 只迁移 MySQL，业务 CRUD 使用 MySQL，向量读写只使用 PostgreSQL。

行动：我根据异常中的 `relation does not exist` 和连接池日志定位到自动装配选错连接，而不是表迁移缺失。随后显式定义 primary MySQL DataSource、JdbcTemplate 和 NamedParameterJdbcTemplate，并给四个业务 Repository 加 Qualifier；向量 Repository 固定使用 vectorJdbcTemplate。

结果：真实启动时 Flyway 正确连接 MySQL 8.4，VectorPool 单独连接 PostgreSQL，知识库创建、模型查询、向量写入和检索全部恢复。这个问题让我意识到多数据源不能只标一个 DataSource，还要检查上层 JDBC 模板和每个仓储的注入点。

## 高频追问

问：为什么 AgentVersion 要复制模型字段？答：为了形成发布快照。只存 modelProfileId 会导致模型配置更新后历史版本含义改变。字段冗余换来可复现和可解释。

问：为什么不用 Spring AI？答：当前只需要一个可控的 OpenAI 兼容流式入口，直接 HttpClient 更轻，异常和 SSE 解析路径透明。未来供应商增多时可在 StreamingModelGateway 后增加适配器。

问：为什么 SSE 不用 WebSocket？答：当前是服务端单向推送文本和状态事件，SSE 基于 HTTP、复杂度更低。需要双向实时控制时再考虑 WebSocket。

问：为什么工具调用不用框架自动执行？答：Agent 平台的关键不是“能调用函数”，而是掌握授权、参数、超时、步骤和失败语义。显式循环让模型只负责提出请求，平台拥有执行权，也更容易接入审批和审计。

问：为什么还要单独做 SafeExecutionGateway？答：如果 BUILTIN、MCP、SSH 和 Coding 各自处理参数、风险与审批，就会出现绕过路径。统一网关固定 Schema 校验、风险判断、审批、取消、限时执行和审计顺序，适配器只实现具体能力，因此新增工具不会重新发明安全链。

问：RunStep 和 AuditEvent 有什么区别？答：RunStep 面向智能体运行语义，记录模型调用、工具请求和 Observation；AuditEvent 面向安全决策，记录请求为何被接受、等待、跳过、执行、失败或终止。审计只保存参数哈希和结果摘要，避免复制敏感原文。当前没有身份和防篡改，所以是本地结构化审计，不是企业合规审计。

问：为什么批准按钮不能只保存一个布尔值？答：因为模型请求可能在等待期间被替换或重放。ApprovalRequest 保存规范化的原始参数和 SHA-256，执行前用同一哈希原子消费 APPROVED 状态；这样批准的是用户看到的这一次具体调用，而不是对工具的永久放行。

问：高风险审批已经等于安全平台了吗？答：不是。当前证明的是单机环境中的参数绑定、拒绝、过期和一次性消费；还没有登录身份、RBAC、策略引擎、跨重启等待恢复和远程执行隔离，不能夸大成企业级治理。

问：运行取消是怎样实现的？答：取消接口先把数据库状态写成 CANCEL_REQUESTED，再由 RunControlService 向 runId 对应线程发中断。ChatService 在模型、审批和工具边界检查终止信号，最终区分 CANCELLED 与 TIMED_OUT，并保存 RUN_TERMINATION。这样数据库状态与执行线程都有控制，不只是前端停止显示。

问：怎样避免取消和正常完成同时发生时互相覆盖？答：仅靠“完成前再检查一次”仍有检查—写入竞态，因此最终状态更新带数据库条件。普通 COMPLETED/FAILED 不能从 CANCEL_REQUESTED 或任何终态更新；取消、超时和中断收口才允许从非终态进入对应终态。谁先完成合法的原子迁移，后续写入就不能反转结果。

问：为什么不宣称已经支持崩溃恢复？答：启动时会识别旧进程的非终态记录并关闭为 INTERRUPTED，避免一直显示运行中，但不会重放模型调用或副作用工具。真正续跑需要持久化检查点、幂等工具和外部调用去重，当前证据不足，所以称为遗留状态收口而不是断点恢复。

问：线程中断能绝对保证立即取消吗？答：不能，它是协作式机制。平台在主要边界反复检查，Java HttpClient 和当前工具会响应中断；MCP 已使用带超时的 HTTP 调用，但远端 Server 是否立即停止仍由其实现决定，未来接入 stdio、SSH 或命令工具时也要提供各自的取消句柄和进程终止策略。

问：工具版为什么不是逐 token 流式？答：每轮必须先得到完整 tool_calls 才能安全执行，所以第一阶段使用非流式决策请求，最终文本以单个 delta 返回。普通无工具路径仍是 token 流式；后续可在供应商协议稳定后增加流式 tool-call 聚合。

问：为什么 MCP 工具默认全部高风险？答：远端 Server 提供的名称、描述、Schema 和 annotations 都是外部输入，平台不能仅凭 readOnlyHint 就替用户降低权限。首版先保证每次调用展示具体参数和目标并逐次批准；以后有可信 Server 白名单和策略配置后，再允许用户显式降级。

问：MCP Server 更新工具后，旧 AgentVersion 会怎样？答：平台用远端名称、标题、描述和 Schema 计算指纹。描述不变时同步复用同一工具修订；任何会影响模型选择或参数的变化都会产生新平台名，旧版本仍引用旧目录记录。若远端已移除该工具，旧版本调用会明确失败而不是静默换成新能力。

问：为什么先做 Streamable HTTP、再做 stdio？答：HTTP 先验证协议生命周期、动态工具目录和统一安全链；stdio 还要管理子进程参数、环境、工作目录、stderr、取消和强制终止，风险边界不同。第二阶段复用同一 McpTransportClient 抽象和 ToolRegistry 加入 stdio，既控制每阶段变量，又证明传输扩展不会复制安全链。

问：stdio MCP 为什么不用一条完整命令字符串？答：完整字符串通常需要交给 shell 解析，会把配置入口扩大成命令注入面。平台分别保存可执行程序和参数数组，ProcessBuilder 直接启动，并拒绝 cmd、PowerShell、bash 等解释器。密钥也只保存环境变量引用，不保存值。

问：为什么 stdio 每次调用重新启动进程？答：短生命周期带来额外初始化延迟，但容易界定 stdout/stderr、超时、取消和退出，避免常驻子进程泄漏或跨调用状态污染。现阶段先要正确隔离；有真实性能瓶颈后才能设计带健康检查和并发隔离的进程池。

问：MCP Server 为什么不能总是直接删除？答：AgentVersion 保存工具平台名作为不可变快照引用。若删除已被草稿或历史版本引用的 Server 和目录，运行详情会失去解释依据。平台允许停用，但只物理删除完全未引用的 Server，这是可维护性与可追溯性的取舍。

问：MCP 的 Tools、Resources 和 Prompts 有什么区别？答：Tools 由模型选择，但平台掌握执行与审批；Resources 是应用控制的上下文，用户预览后才能导入知识库；Prompts 是用户控制的模板，必须主动选择和填写参数。三者都由 Server 提供，但控制权不同，所以不能全部塞进自动 ReAct 链。

问：为什么 Resource 导入复用 KnowledgeService？答：如果 MCP 另建解析和向量化旁路，会绕过 20 MB 限制、Tika、切块、索引版本和错误处理。统一内容入口让上传文件和远端 Resource 只在“字节从哪里来”上不同，后续数据链保持一致。

问：为什么配置导出不包含密钥？答：平台从一开始只保存环境变量名。导出文件包含 HTTP Bearer Token 的变量名，或 stdio 子进程变量到宿主变量的名称映射，真正值仍由启动环境提供，因此配置文件可以迁移但不能直接泄露凭据。

问：前端现在能保存密钥，为什么仍然说数据库不保存明文？答：前端只是一次输入入口，值直接提交本机后端；后端用 Windows DPAPI 加密并写入独立的 `data/secrets`，MySQL 和 API 只处理凭据名称与配置状态。模型和 MCP 通过统一 SecretResolver 读取，环境变量优先、安全存储次之。页面不会读取或回显旧值。

问：为什么选择 DPAPI，不直接加密后把密钥放 MySQL？答：应用自己管理一个通用主密钥会产生新的密钥分发问题。DPAPI 把解密能力绑定当前 Windows 用户，符合单机桌面定位；密文与业务备份分离也减少普通数据库查询暴露。代价是不能直接跨电脑或跨用户迁移，目标机器需要重新输入。

问：为什么历史 AgentVersion 不直接删除？答：Conversation 和 AgentRun 都绑定精确版本，直接删除会破坏运行复现和外键。平台先用归档解决新会话列表噪声；只有非最新版、已归档、且没有会话或运行引用的误发版本才允许永久删除。有历史使用的版本可以恢复或保持归档，但不能抹掉。

问：归档是否违反不可变版本？答：不违反。不可变约束针对模型、提示词、知识库和工具快照；`archived_at` 是版本是否允许用于新会话的生命周期元数据，不改变历史运行配置。归档后旧运行仍按原版本读取。

问：现在能否说完整支持 MCP？答：不能。当前完成的是 `2025-06-18` 下两种传输的 Tools、Resources、Prompts 和本地管理闭环；OAuth、sampling、elicitation、roots、resource templates、订阅通知和长 session 池仍未实现。特别是 OAuth 需要 PKCE、资源指示器、浏览器回调和安全令牌存储，不能用一个文本框冒充完整实现。

问：RAG 为什么分三种存储？答：MySQL 管业务关系，本地文件保原件，pgvector 管可重建的检索索引。职责清晰，但跨存储一致性需要后续补偿机制。

问：词法哈希算 embedding 吗？答：它产生固定维度、可做向量距离的数值表示，但不是训练得到的语义 embedding。它是零依赖检索基线，不能夸大语义能力。

问：为什么换了 Qwen 还不把无答案阈值调高？答：阈值扫描显示误召回下降时 Recall 也明显下降，正负样本分数重叠。固定阈值不是充分的相关性判别，需要独立开发集、分数间隔、rerank 或回答阶段证据判断。

问：为什么 Qwen 没有默认加检索 instruction？答：不是模型不支持，而是本项目在知识包扩充前的同语料消融显示，统一中文前缀让 MRR 从 0.8160 降到 0.6917。保留配置能力，但生产默认选择实测更好的无前缀方案；知识包扩充后也用无前缀配置重新建立了最终结果。

问：最有价值的工程决策是什么？答：先用不可变版本和清晰数据边界稳定运行语义，再扩展 RAG；同时把“已实现”和“规划中”写入验证文档，避免演示能力与真实能力不一致。

问：为什么当前可以作为成熟锚点？答：因为配置发布、RAG 来源、显式工具循环、参数审批、运行终态、动态 MCP、安全凭据和运维验证已经形成互相连接的闭环，并有 31 个测试、真实 DeepSeek/Ollama/Tavily 验收和故障复盘支撑。它仍是正式版候选，成熟不等于企业级或功能全部完成。

问：下一阶段为什么先做会话附件，而不是立刻做 SSH？答：会话附件直接解决高频使用摩擦，且能复用 Tika、来源展示和向量隔离；SSH 会扩大到远端命令和提权副作用，需要更成熟的策略与沙箱。先补日常上下文体验，再增强 RAG 证据质量，最后扩张高风险能力，收益与风险更匹配。
