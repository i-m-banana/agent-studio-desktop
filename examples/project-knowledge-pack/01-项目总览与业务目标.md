# Agent Studio Desktop：项目总览与业务目标

## 一句话定位

Agent Studio Desktop 是一个运行在个人电脑上的智能体搭建与调试工具。用户不需要修改 Java 代码，就能配置 OpenAI 兼容模型、系统提示词和知识库，发布一个固定版本的 Agent，并在本地网页中流式对话、查看检索来源。

它不是公网 SaaS，也不是高并发多租户平台。产品的核心价值是让“模型连接、提示词、知识和版本”变成可配置资产，同时让本地开发环境简单、过程可观察、结果可验证。

MCP 把“能力可扩展”从代码能力变成用户能力。用户可连接 Streamable HTTP 或本机 stdio Server，平台协商协议并发现 Tools、Resources 和 Prompts。工具像内置能力一样进入 Agent Builder，Resource 可预览或导入知识库，Prompt 由用户填写参数后主动生成消息。模型可以按 Schema 请求工具，但真正执行仍由平台掌控；新发现的 MCP 工具默认高风险。

## 为什么要新建工程

三个来源项目分别积累了 RAG、SSH 和 Coding 方向的经验，但也存在多 Maven 模块、复杂 DDD、动态 Spring Bean、策略树过多、安全链尚未闭环或源码状态不统一等问题。直接在旧工程上继续堆功能，会同时继承历史复杂度和不清晰的能力边界。

因此项目采用独立目录和独立 Git 仓库，从最小主链开始：先证明模型配置、Agent 发布和流式对话，再增加 RAG。每一阶段都保存构建结果、真实异常、修复过程和未实现项。

## 当前用户流程

用户首先在“模型与凭据”页面填写显示名称、兼容 API 地址、模型名称、凭据名称和温度。真正密钥可以由启动后端的环境变量提供，也可以从前端一次性提交给后端并使用 Windows DPAPI 加密保存；环境变量优先。数据库和接口不保存或回显密钥明文。

随后用户在“知识库”页面创建知识库，上传 TXT、Markdown、PDF 或 DOCX 等文档。后端保存原始文件，用 Apache Tika 提取文本，切分并向量化，然后把 chunk 写入 PostgreSQL + pgvector。

用户在 Agent Builder 中选择模型、可选知识库和工具，填写系统提示词并创建草稿。发布后生成不可变 AgentVersion，模型、提示词、知识库和工具集合都被冻结。旧版本可以归档和恢复，只有未使用的非最新版才允许在归档后永久删除。对话测试台默认只列每个 Agent 最新版本，也可显式展开历史版本。服务端先检索知识库；若版本绑定工具，则由显式 ReAct 循环处理模型 tool call、平台执行和 Observation，并通过 SSE 返回来源、运行步骤和答案。LOW/READ 工具可直接执行；HIGH/WRITE 工具展示完整参数并等待审批。运行开始后可以主动停止，超过总时限也会终止；结束后可从运行记录查看状态和完整步骤。

## 当前技术栈

- 后端：Java 21、Spring Boot 3.4.3、Maven、Spring JDBC、Flyway；
- 前端：React 19、TypeScript、Vite；
- 业务数据库：MySQL 8.4；
- 向量数据库：PostgreSQL 17 + pgvector；
- 文档解析：Apache Tika 3.1.0；
- 模型接口：OpenAI Chat Completions 兼容 SSE，已用 DeepSeek 实测；
- Embedding：本机 Ollama `qwen3-embedding:0.6b`，1024 维；
- 本地运行：Windows + Docker Desktop。

## 当前边界

项目已从纯 RAG 对话工具进入带动态工具、受控副作用和运行治理的阶段，但还不是完整工具型 Agent 平台。MCP Streamable HTTP 与 stdio 的 Tools/Resources/Prompts、统一安全执行网关、参数绑定审批、结构化审计、主动取消、总超时和历史详情已经形成闭环；锚点后又完成并真实验收本地 Coding 浏览/精确补丁/固定验证，以及 SSH/SFTP 远程只读工作区和受审单文件精确补丁。系统仍没有登录与 RBAC、MCP OAuth 扩展、stdio OS 沙箱、远程 Shell/Git/构建/部署、断点续跑和通用策略引擎。最初使用 384 维词法哈希跑通零外部 embedding 依赖的闭环；冻结题集证明其改写题排序较差后，生产默认升级为 Ollama `qwen3-embedding:0.6b`。Qwen 的召回和排序优于 LocalHash，但无答案误召回仍未解决；最终数值和语料哈希记录在评测报告与 11 号文档中。
