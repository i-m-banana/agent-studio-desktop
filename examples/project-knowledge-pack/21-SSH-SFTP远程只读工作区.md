# SSH/SFTP 远程只读工作区

## 已实现

SSH 第一阶段新增三个来源为 `SSH`、能力为 `READ`、风险为 `LOW` 的内置工具：远程目录浏览、按文件名或路径搜索、UTF-8 文本分段读取。它们通过 Apache MINA SSHD 建立 SSH 会话并使用 SFTP 文件协议，不属于 MCP，也不执行远程终端命令。

一个应用实例只配置一个远程目标和一个非根目录的授权工作区。用户可在页面填写主机、端口、用户和远程根，配置由 V11 保存到 MySQL；密码独立进入 Windows DPAPI 安全凭据。页面可在不发送密码的情况下探测主机公钥，但必须由用户在应用外核对 SHA-256 指纹后保存。环境变量保留为部署回退。模型只看到工具描述、远程目标标识和受限结果，不会收到密码。

远程路径仅接受 POSIX 相对路径，从授权根到目标逐级 `lstat` 并拒绝符号链接；密钥目录、`.env`、`data/secrets` 和私钥后缀受保护。搜索不读取内容，限制为 3000 项和 16 层并跳过常见依赖/构建目录；读取限制为 1 MiB、有效 UTF-8、500 行和约 16000 字符。

测试使用进程内真实 SSH/SFTP Server 完成握手、无凭据指纹探测、密码认证、SFTP 浏览/搜索/读取和摘要输出，并覆盖错误主机指纹、越界路径与敏感文件拒绝。控制器测试覆盖 V11 页面配置持久化和根目录拒绝；全量后端 51 个测试及前端生产构建通过。三个工具由原 ToolRegistry 注册，AgentVersion 固化后仍走 SafeExecutionGateway、RunStep 与 AuditEvent；目标环境显示具体 SSH 用户、主机、端口和授权根。

## 尚未完成

真实 Ubuntu 服务器和模型已经完成三次正向、两次反向验收。目录浏览、路径搜索和分段读取均留下完整 RunStep/AuditEvent；错误指纹形成失败工具结果和失败审计。越界请求由模型在发起工具调用前拒绝，因此该条只能证明 Agent 行为正确，工具层强制拒绝仍引用自动化证据。

截至本阶段，仍没有密钥认证、多连接配置、远程 Shell、文件内容搜索、写入/上传/删除/重命名、受审补丁、Git 操作、远程构建测试、日志命令、Docker/Nginx 部署、健康检查和回滚。因此简历中“远程命令执行、配置修改、日志排查、编译及单元测试、Docker/Nginx 操作、网站部署及结果验证”仍不能记为已覆盖。
