# 安全凭据与版本生命周期

## 这次改动解决了什么

正式使用 Tavily 和 DeepSeek 后暴露出两个桌面产品问题：第一，用户不应每次启动都在 PowerShell 重新设置密钥；第二，Agent 连续发布 v1、v2 后，历史版本会一直堆在对话下拉框中，但粗暴删除又会破坏运行记录。

项目没有把密钥直接保存到前端或 MySQL，而是增加统一凭据解析层。用户在“模型与凭据”页面输入一次，后端使用 Windows DPAPI 加密，密文只能由当前 Windows 用户解密。业务表、MCP 配置和 Agent 版本仍只记录 `DEEPSEEK_API_KEY`、`TAVILY_API_KEY` 这类名称。API 只返回是否已配置和来源，不返回密钥值。运行时先读进程环境变量，再读安全存储，所以开发者仍能用环境变量临时覆盖。

这个设计的面试要点不是“做了一个密码输入框”，而是把密钥的输入、保存、解析和展示分层：前端不可持久化明文；后端集中解析，避免模型、HTTP MCP、stdio MCP 和系统诊断各自形成不同规则；安全存储与业务数据库分离；密钥状态可见但值不可回显。

AgentVersion 的内容快照仍然不可修改，新加的是生命周期状态。对话测试台默认只展示每个 Agent 的最新版本，用户打开“显示历史版本”后才看到仍未归档的旧版。Agent Builder 可以归档旧版本，归档版本不再用于新会话，但历史运行仍可按原版本读取。

永久删除采用三道约束：必须先归档、不能是最新版、不能有 Conversation 或 AgentRun 引用。若版本已经真正运行过，只能归档不能删除。这样既解决版本列表噪声，又保存审计与复现能力。对于刚误发、从未使用的旧版本，先发布替代版本再归档，即可永久删除。

## 如何验收

首次不设置环境变量启动，在“模型与凭据”保存 DeepSeek 或 Tavily 密钥，刷新页面只能看到“安全存储”，看不到值；重启程序后仍显示已配置且真实调用成功。随后从外部设置同名环境变量并重启，应显示“环境变量”，证明覆盖顺序生效。

为 Agent 发布 v1、v2。对话页默认只出现 v2；勾选“显示历史版本”后出现 v1 和 v2。回到 Agent Builder 归档 v1，v1 即使打开历史开关也不再用于新对话。未运行过的 v1 会出现永久删除入口；已经产生会话或运行的版本只允许归档和恢复。最新版 v2 的归档请求必须被拒绝，直到先发布 v3。

## 取舍与边界

DPAPI 绑定 Windows 用户，因此复制整个数据目录到另一台电脑并不会同时迁移可用密钥，这是安全属性而非缺陷。正式迁移时应在目标电脑重新输入。当前是单机桌面架构，不宣称提供企业级多人密钥托管。
