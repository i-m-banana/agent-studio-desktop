# Agent Studio Desktop：只新增远程发布前备份

## 阶段结论

只读部署诊断人工验收后，项目实现生产发布链的下一道闸门：固定创建型远程备份。`prepare_remote_deployment_backup` 没有模型参数，统一经过 AgentVersion、ToolRegistry、SafeExecutionGateway、一次性 HIGH 审批、RunStep 和 AuditEvent。后端 75 个测试与前端测试/生产构建通过；真实生产服务器连续两次创建不同备份目录，第一次完成人工只读校验，第二次由工具在成功返回前自动校验摘要，创建型备份已人工验收。

## 为什么只允许创建

备份工具最危险的能力不是写入，而是覆盖、删除和误恢复。平台让服务器生成时间戳加随机后缀的 backupId，并用独占新目录落盘；模型不能提供目录、名称、命令、参数或环境变量。失败现场保留并带 `FAILED` 标记，不自动清理。首版也没有历史保留策略，避免错误策略删除唯一恢复点。

## 固定备份内容

MySQL 通过容器内部环境变量执行一致性逻辑导出，密码不进入命令结果；uploads 生成压缩包；app.jar、Dockerfile、Compose、Nginx 配置和 `.env` 被复制到新目录，`.env` 权限固定为 0600且内容不回传；同时记录镜像与四个固定服务状态。九个负载文件进入 SHA256SUMS，manifest 另有摘要。数据库和 uploads 必须非空，回执格式也必须严格校验。

## 当前边界

当前没有备份删除、覆盖、下载、自动清理、数据库还原、uploads 恢复、发布或回滚。真实运行 `925e6062-e1a4-432f-8c29-fc456967952b` 与 `c19eb39f-a2b9-406c-94d4-2d10e9d194d9` 分别创建 `20260921T142020Z-207e3ede` 和 `20260921T143308Z-5b8b3432`，验证了连续创建不会复用目录。恢复能力仍必须等待独立恢复演练，不能从“备份创建成功”推导为“网站一定可以恢复”。
