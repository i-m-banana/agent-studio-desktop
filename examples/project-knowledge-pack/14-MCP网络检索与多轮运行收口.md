# MCP 网络检索与多轮运行收口

## 真实场景

项目通过 Streamable HTTP 连接 Tavily MCP，Endpoint 使用 `https://mcp.tavily.com/mcp`，Bearer Token 配置凭据名 `TAVILY_API_KEY`。DeepSeek 负责决定何时搜索和整理答案，Tavily 负责 search、extract 等实时网络能力。密钥值可由进程环境或 Windows DPAPI 安全存储提供，不进入 MySQL。

第一次集中测试询问 MCP 官方规范最新版本。Tavily search 已返回结果，因此额度正常扣减；DeepSeek 随后请求 extract，但新的高风险调用需要另一张一次性审批。审批卡当时位于滚动消息区顶部，用户未看到，90 秒后过期；模型继续尝试工具，整个运行在 120 秒达到总时限。

第二次测试手动批准了全部请求。模型面对搜索结果中的旧镜像与新官方页面冲突，执行多次 search，再提取官方规范和 GitHub Release。四个工具轮次全部成功，最后已经得到 `2026-07-28` 的官方发布证据，但旧运行器在第四轮完成后直接抛出上限错误。这说明外部连接和审批均正常，缺陷位于 ReAct 循环的最终状态转换。

## 修复设计

审批卡改为 sticky，无论消息区滚动到哪里都保持可见；浏览器标题显示“待审批”，卡片每秒更新剩余时间，过期后按钮禁用。它没有把一次批准扩大成整次运行授权，每个 HIGH 工具的具体参数仍需单独批准。

工具轮数仍限制为四轮，避免模型无限搜索和持续消耗额度。不同之处是最后一轮工具完成后，运行器清空可用工具列表，加入“仅依据已有结果回答”的系统指令，再调用模型一次。成功答案以 `MODEL_FINALIZATION` 记录；模型在无工具定义时仍请求工具或返回空正文，才被安全判为失败。

工具输出分为两个用途：运行记录只保存最多 4000 字符，保证页面和数据库可控；提供给模型的观察最多 16000 字符，让 Tavily 的多来源标题、URL 和摘要有更大概率完整保留。超长结果会带明确截断标记。这比直接提高最大轮数更节省调用额度，也比把完整任意外部正文无限塞进上下文更安全。

## 面试表达

可以把这次问题概括为：“真实网络 MCP 测试让我发现，工具执行成功不等于 AgentRun 能正确结束。旧实现把 max rounds 同时当成工具预算和模型总轮数，最后一批观察没有机会被消费。我将它改成有限工具预算加一次无工具收尾，并把审批可见性、倒计时以及模型上下文截断与审计截断分开处理。最终既维持了参数绑定审批和循环保护，也避免丢弃已经付费获得的搜索结果。”
