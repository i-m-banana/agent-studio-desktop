# Agent Studio Desktop：成熟版本开发锚点与面试全景

## 锚点定义

本文把 2026-09-07 的 `1.0.0-rc1` 作为后续开发的知识锚点。这里的“成熟”指：核心主链已经形成、关键状态可以追踪、危险副作用受平台控制、真实外部模型与 MCP 已跑通、自动化和运维入口已经具备；它不等于功能全部完成，也不等于已经通过最终 `1.0.0` 人工发布清单。

锚点时的可核验工程规模是：后端 118 个主 Java 源文件、19 个测试源文件、Flyway V1–V10、31 个自动化测试全部通过；前端 React + TypeScript 生产构建通过。真实环境曾完成 DeepSeek 对话、Ollama Qwen embedding、MySQL、pgvector、内置工具审批、MCP HTTP/stdio 及 Tavily 网络检索。最新增加的 Windows DPAPI 凭据与 MySQL V10 仍需在用户日常数据库做最后一轮人工验收。

本文在 `1.0.0-rc1` 写成时只是一份知识和事实口径锚点；此后正式版验收、提交和 `v1.0.0` 注释标签已经完成，当前可精确回退到提交 `3488f08`。下节单独记录锚点后的开发，避免改写 rc1 当时的证据。

## 锚点后的已验证进展

正式版现已由注释标签 `v1.0.0` 指向提交 `3488f08`。2026-09-14 从该提交创建 `feat/coding-workspace`，实现 Coding 只读第一阶段：受控单根本地工作区、目录浏览、文件路径搜索和 UTF-8 文本读取，并复用 AgentVersion、ToolRegistry、SafeExecutionGateway、RunStep 与 AuditEvent。首轮真实搜索发现根目录性能问题并完成轻量剪枝优化，真实浏览、读取和修复后的根目录搜索均通过。2026-09-15 又实现并验收摘要绑定、精确匹配、HIGH 审批与原子替换的单文件文本补丁；当前全量后端为 41 个测试通过，真实批准、恢复和拒绝运行均有记录。通用 diff、文件新建/删除、命令、构建测试、SSH/SFTP 与部署仍未实现。

## 一句话定位

Agent Studio Desktop 是一个单机优先、配置驱动、强调版本可复现和工具安全治理的智能体搭建平台：用户可以配置 OpenAI 兼容模型、知识库和 MCP 工具，发布不可变 Agent 版本，在浏览器中进行带来源、审批、运行步骤和审计记录的对话。

## 用户真正得到的能力

用户不需要修改 Java 代码，就能完成以下工作：

1. 配置 DeepSeek 等 OpenAI Chat Completions 兼容模型；
2. 在前端安全保存 API Key，后续启动不必重复输入；
3. 创建本地知识库，上传 Markdown、TXT、PDF、DOCX 等文档；
4. 使用 Ollama 的 Qwen embedding 建立 pgvector 索引，并查看每次回答的来源 chunk；
5. 创建 Agent 草稿，绑定模型、知识库、内置工具或 MCP 工具；
6. 发布不可变版本，修改草稿不会改变历史运行；
7. 默认使用最新版本对话，也能查看、归档和恢复历史版本；
8. 在模型请求高风险工具时查看原参数并逐次批准或拒绝；
9. 取消长运行，查看超时、失败、工具结果、审批决定和安全审计；
10. 接入 Streamable HTTP 或本机 stdio MCP，使用 Tools、Resources 和 Prompts；
11. 通过 Tavily 一类 MCP Server 查询实时网络信息，并在工具预算结束后基于已有证据收口回答；
12. 使用系统诊断、一键启动/停止、备份和发布检查完成日常运维。

## 系统结构

前端是 React + TypeScript + Vite 单页管理台。后端是 Java 21 + Spring Boot 模块化单体，按模型、Agent、知识、会话、运行、审批、执行、MCP、密钥和系统诊断划分包边界。模块化单体保留了清晰职责，又避免项目早期引入远程调用、分布式事务和多服务部署成本。

数据被有意分为三类：MySQL 保存 ModelProfile、AgentDefinition、AgentVersion、Conversation、Message、AgentRun、RunStep、ApprovalRequest、AuditEvent 和 MCP 目录；PostgreSQL + pgvector 保存可重建的知识 chunk 向量；本地 `data` 保存原始文档、受控工具文件与 DPAPI 密文。选择三种存储不是为了堆技术，而是让业务关系、向量索引和文件原件各自使用合适的数据模型。

## 五条核心运行链

### 1. 配置与发布链

ModelProfile 保存连接参数和凭据名称。AgentDefinition 是可编辑草稿，包含模型、知识库、系统提示词和工具集合。发布时创建新的 AgentVersion，把运行所需配置复制为快照。会话永久绑定一个 AgentVersion，所以模型配置或草稿后来变化时，历史行为仍可解释。

版本内容依旧不可变，生命周期则允许归档。对话默认只列每个 Agent 的最新未归档版本；打开历史开关才显示旧版本。归档阻止创建新会话但不影响历史记录。永久删除必须同时满足“不是最新版、已经归档、没有 Conversation 或 AgentRun 引用”。

### 2. 普通对话与 SSE 链

浏览器提交 AgentVersion、可选 Conversation 和消息。后端固定会话版本，写入用户消息，调用模型并通过 SSE 推送 `run`、`delta`、`done` 或错误事件。无工具普通回答保持 token 流式输出；工具型回答需要先得到完整 tool calls，因此决策轮使用非流式完成，最终文本再通过统一事件返回。

### 3. RAG 链

文档先由 Tika 抽取文本，再由重叠切块器生成 chunk，EmbeddingGateway 调用本机 Ollama Qwen，VectorChunkRepository 写入带知识库和索引版本的 pgvector 表。查询时只检索 AgentVersion 绑定的知识库，返回 top-k 候选和相似度，再把来源作为 `sources` 事件展示。

项目先用 384 维 LocalHash 跑通零依赖闭环，再用冻结 30 题做 embedding-only 对照。Qwen 对低词面重合改写的 Recall 和 MRR 明显更好，因此升级为默认 1024 维语义向量。查询 instruction 也做过消融；统一中文前缀曾使 MRR 从 0.8160 降至 0.6917，所以默认关闭而不是凭经验开启。

当前已有两层拒答保护：没有候选时确定性拒答，不调用模型；有候选时向模型注入证据契约。但冻结负例的检索误召回率仍曾达到 100%，说明“总能找出最近邻”不等于“证据足够”。这是后续混合检索、rerank 和 evidence judge 的主要依据。

### 4. 工具、审批与运行治理链

模型只能提出工具调用，不能直接执行。ChatService 编排显式 ReAct 循环，ToolRegistry 解析版本允许的工具，SafeExecutionGateway 固定执行 Schema 校验、风险判断、参数绑定审批、取消检查、独立超时、具体调用和 AuditEvent。工具结果作为 Observation 回给模型。

LOW/READ 的 `current_time` 用于验证无副作用链路；HIGH/WRITE 的 `write_workspace_note` 只能在受控目录创建白名单文本文件，并禁止覆盖和路径穿越。高风险批准绑定规范化参数 SHA-256，只能原子消费一次；拒绝或过期不会产生副作用。

AgentRun 和 RunStep 记录模型、工具、审批和终止过程。RunControlService 以 runId 绑定线程和总截止时间，用户可以主动取消，默认 120 秒超时。最终状态更新带数据库条件，避免 CANCEL_REQUESTED 与 COMPLETED 的竞态覆盖。重启会把遗留运行关闭为 INTERRUPTED，但不会冒充真正的断点续跑。

### 5. MCP 动态能力链

MCP 不是旁路执行器。Streamable HTTP 和 stdio 先发现 Server 的 Tools、Resources、Prompts，再把工具转换为平台 ToolDescriptor，进入同一个 ToolRegistry 和 SafeExecutionGateway。这样动态工具继续受到版本绑定、Schema、审批、超时、取消和审计约束。

远端工具名通过 Server 命名空间和描述/Schema 指纹转成稳定平台名，防止跨 Server 重名和更新覆盖旧版本。所有新 MCP 工具默认 HIGH，用户确认信任后才能显式降级。Resources 由用户预览并复用 KnowledgeService 导入知识库；Prompts 由用户主动选择、填参和获取，不能被模型暗中执行。

stdio 使用程序路径和参数数组直接启动，不拼接 shell 命令；每次操作使用短生命周期子进程并分级回收。HTTP 支持 `2025-06-18` initialize/initialized、分页目录、JSON 或 SSE 响应、Session ID、协议头和尽力关闭。

## 安全凭据设计

前端只是密钥输入界面，不在 localStorage、sessionStorage 或业务数据库保存值。后端 SecretStore 用 Windows DPAPI 加密，密文绑定当前 Windows 用户并写入 `data/secrets`。SecretResolver 是唯一解析入口，顺序为进程环境变量、DPAPI、安全缺失。模型网关、HTTP MCP、stdio 子进程注入和系统诊断都复用该规则。

接口只返回凭据名、是否配置、来源及被哪些配置引用，不返回明文。环境变量用于部署和临时覆盖；安全存储用于桌面日常体验。复制数据目录到另一台电脑不会带来可直接解密的密钥，这是边界设计而不是迁移功能。

## 最有代表性的工程问题

### Windows 数据库端口连续冲突

MySQL 先后在 3306、13306 被本机进程占用，最终改用 23306；pgvector 使用 15432，并允许 `.env` 覆盖。经验是桌面开发环境不能假设默认端口空闲，配置、Compose 和后端默认值必须同步。

### 双数据源自动装配连错库

加入 pgvector 后，业务 Repository 一度使用了错误的 JDBC 模板。通过连接池日志和 `relation does not exist` 定位为依赖注入边界，而不是迁移缺表。最终显式定义 PrimaryPool、VectorPool、两组模板和 Qualifier，使 Flyway/业务表只进 MySQL、向量只进 PostgreSQL。

### 可选知识库空字符串触发外键错误

创建不同名 Agent 仍提示名称或引用无效，真正原因是“不使用知识库”从前端提交空字符串，后端把它当外键 ID。修复是在前端传 null、后端统一归一化可选 ID，并补回归测试。这体现了不能根据复合错误提示直接猜根因。

### 文档解析把异常压成“未知错误”

日志只显示服务正常，页面却报解析失败。排查区分上传、Tika、embedding、pgvector 和状态回写阶段，并改进错误透传。经验是异步/多阶段任务必须保存阶段状态与根因，不能只给一个兜底提示。

### 长运行审批不可见与超时

Tavily search 已成功并扣额度，但后续 extract 审批卡在滚动区域顶部，用户没有看到，90 秒后过期并引发重试，最终碰到 120 秒总时限。修复为 sticky 审批卡、浏览器标题提醒和秒级倒计时。

### 最大工具轮数丢弃成功结果

用户批准全部 Tavily 操作后，第四轮已经得到足够证据，运行器却在循环边界直接报“达到最大工具轮数”。修复不是无限增加预算，而是在预算耗尽后移除工具，追加一次 `MODEL_FINALIZATION`，强制模型用已有结果总结。同时把审计展示截断和模型 Observation 上下文分离，避免因 4000 字展示限制导致重复搜索。

### 一键启动的三次 Windows 差异

发布检查的原地 `npm ci` 曾破坏正在使用的 node_modules；Vite 缺失后启动失败；Vite 又可能只监听 IPv6 localhost，导致 IPv4 健康检查误报；隐藏 PowerShell 还可能因 Maven 设置窗口标题抛 HostException。最终发布检查改在受控临时副本执行，一键启动补依赖、明确绑定 127.0.0.1、使用隐藏 cmd，停止脚本容忍进程竞态。

## 为什么这个版本可以称为成熟锚点

成熟度不来自页面数量，而来自六个闭环已经同时存在：配置有发布快照，知识有来源，工具有执行权边界，高风险有审批，长运行有终态，动态 MCP 没有绕开安全层；同时还有诊断、测试、备份和文档证明这些链路。

`1.0.0` 锚点仍不是企业级平台：没有登录/RBAC、多租户、审计签名、MCP OAuth、OS 级 stdio 沙箱、SSH、Coding、临时会话附件、后台任务队列、真正断点续跑和安装包。锚点后的 Coding 只读进展见本文前部；它不改变 `1.0.0` 的发布口径，也不能扩写成通用 Coding。面试中应把这些描述为明确边界和后续路线，而不是遗漏或已经完成的能力。

## 30 秒面试版本

我做了一个本地优先的 Agent Studio，用户能配置 DeepSeek、Ollama RAG 和 MCP 工具，再发布不可变 Agent 版本。项目的重点不是简单调模型接口，而是把版本快照、来源引用、参数审批、取消超时、运行步骤和安全审计串成闭环。后端是 Java 21 与 Spring Boot，MySQL 管业务状态、pgvector 管可重建索引，前端是 React。开发中我用冻结题集决定 embedding 升级，也通过真实 Tavily 运行修复了审批不可见和工具预算收尾问题，目前 31 个后端测试和前端生产构建通过。

## 三分钟讲述结构

第一段讲需求：旧项目能力太重且边界混杂，所以新建独立单机工程，先解决“无需改代码即可配置、发布、对话、追踪”四件事。

第二段讲架构：模块化单体降低早期复杂度，AgentDefinition/AgentVersion 分开解决编辑与复现，三类存储按数据职责拆分，Gateway/Registry 隔离模型、embedding 和工具实现。

第三段讲纵向主链：模型 SSE → 本地 RAG → 显式 ReAct → 参数绑定审批 → 运行取消与审计 → MCP Tools/Resources/Prompts → Tavily 网络检索。

第四段讲工程方法：每阶段都有自动化和真实验收；RAG 用冻结集和消融而非主观调参；安全功能从低风险、受控写入再到动态 MCP 逐级扩展；真实故障形成回归和 ADR。

第五段讲边界：这是单机正式版候选，不是多租户云平台；下一阶段先做会话附件和 RAG 质量，再做 MCP 生产化与 Coding/SSH 垂直样例。
