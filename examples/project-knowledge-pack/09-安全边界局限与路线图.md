# Agent Studio Desktop：安全边界、当前局限与路线图

## 已有安全边界

锚点后 Coding 只读第一阶段增加单根授权工作区。目录、搜索和文本读取只接受相对路径，真实路径必须仍在授权根内；绝对路径、`..`、Windows 数据流、链接逃逸、密钥目录、真实 `.env`、常见私钥、二进制和超限输出会被拒绝。三个工具仍经过统一执行网关和审计，没有单独文件 API。

模型密钥不进入业务数据库和 Git，ModelProfile 只保存凭据名称。后端优先读取启动进程环境，也允许当前 Windows 用户通过前端写入 DPAPI 加密的本机安全存储；状态接口不回显明文。文件保存路径经过绝对化、规范化和 dataRoot 前缀检查，避免通过文件名写出授权目录。上传大小限制为 20 MB，API 请求使用校验注解，外部模型错误文本会截断。

AgentVersion 不可变，会话固定绑定版本，减少运行中配置漂移。知识库检索按 knowledgeBaseId 隔离，不做全库搜索。向量表初始化使用 `IF NOT EXISTS`，不会在应用启动时删除用户索引。HIGH 工具执行前必须经过参数绑定审批；write_workspace_note 只能在受控目录创建白名单扩展名文件，不能覆盖已有文件。

## 当前局限

生产已升级为 Ollama Qwen 语义 embedding，但无答案题仍可能获得看似合理的最近邻。当前 6 个负例的检索误召回率是 100%，固定阈值无法同时保持高 Recall。`1.0.0-rc1` 已增加空召回确定性拒答和候选片段证据契约，这是答案边界而非检索指标优化；有候选片段时仍依赖模型遵守规则。系统没有独立 evidence judge、rerank、BM25、页码和章节级 metadata，文档处理和索引重建目前是同步请求，大文件会占用请求时间。

本地文件、MySQL 和 pgvector 之间没有分布式事务。删除到中间失败时可能出现不一致，目前只会返回明确错误，没有自动补偿和孤儿巡检。知识库没有更新和删除整个库的接口，也没有重复 SHA-256 去重策略。

项目没有登录、RBAC 和多租户，因为定位是个人电脑上的本地工具。它已经有显式 ReAct、统一执行网关、参数绑定审批、AuditEvent、运行收口、MCP 核心闭环、本地 Coding 浏览/受审补丁/固定验证，以及 SSH/SFTP 远程只读能力；远程单文件受审补丁已通过自动化但尚未真实验收。系统仍没有审批人身份、通用策略引擎、MCP OAuth 等扩展、stdio OS 沙箱、SSH 密钥认证/多目标/远程 Shell/Git/构建/部署、断点续跑和长期记忆。AuditEvent 未做签名防篡改和保留策略，不能等同合规审计；本地验证任务仍继承后端用户权限。当前只支持单后端实例。

如果问题是“能否让模型循环调用远程终端工具，并在危险命令前等待批准”，准确答案仍是否定的：平台已建立 SSH/SFTP 文件通道和 HIGH 远程文本补丁，但尚未实现远程终端命令适配器与命令级策略。SFTP 文件能力、MCP 调用和远程 Shell 是三种不同边界。

## 下一步优先级

本节保留能力边界摘要；锚点后的完整阶段、依赖和验收标准见 `17-锚点后的未来开发计划.md`。近期顺序已经收敛为：先完成 1.0.0 真实验收与 Git 标签，再做会话附件、RAG 证据质量和后台索引任务，之后推进 MCP 生产化、运行策略、Coding/SSH 与桌面安装体验。

EmbeddingGateway、中文语义模型、索引版本、重建流程和离线评测集已经完成。RAG 后续优先处理无答案证据充分性，再以独立实验决定章节切块、BM25 和 rerank，不在当前阶段继续无边界调参。

第二优先级的运行控制已经完成最小闭环：AgentRun 有最大轮数、单工具超时、总运行超时、主动取消、终止步骤和历史详情；重启时能关闭遗留状态。通用 Schema 校验和结构化工具审计也已进入统一网关。下一步仍需客户端断开联动取消、真正断点续跑和更多只读工具。

第三优先级的最小安全审批已经完成：HIGH 请求生成参数绑定的 ApprovalRequest，真实拒绝和批准均已人工通过。所有工具现已统一通过 SafeExecutionGateway，并保存不含原参数的 AuditEvent。下一步不是重新做审批，而是补身份、RBAC、策略规则、并发治理，并把相同执行门用于 EXECUTE、PRIVILEGED 类型工具。

MCP 已完成两种传输下的 Tools、Resources 和 Prompts，并可编辑、启停、受保护删除、查看同步历史、导入导出无秘密配置和显式调整单工具策略。下一步应基于实际 Server 补 OAuth、resource templates、list_changed 订阅、sampling/elicitation/roots 和按证据决定的 session/进程池，并为 stdio 增加 OS 沙箱、资源配额和可信程序白名单；这些能力未完成前不能概括为“完整兼容所有 MCP Server”。

Coding 已完成并真实验收单根本地工作区浏览、受审精确补丁和固定 Maven/npm 验证。SSH/SFTP 只读阶段也已真实验收，远程受审单文件补丁正在人工验收前阶段；下一步才是受限远程验证、Git 与部署闭环。所有能力都必须走统一执行网关，不能“先执行后审计”。

## 如何回答“为什么没有一次做完”

因为 Agent 平台的复杂度主要来自状态和副作用。项目先完成无工具的可验证闭环，再用无副作用工具验证版本快照、循环、超时和步骤状态；之后只增加一个受控目录写工具验证审批、拒绝和参数绑定。命令执行与远程能力继续等待身份和更完整的策略门。这种分层扩展让每次新增风险都能被单独验证。
