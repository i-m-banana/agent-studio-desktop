# Agent Studio Desktop：安全边界、当前局限与路线图

## 已有安全边界

模型密钥不进入数据库和 Git，ModelProfile 只保存环境变量名称。后端在模型调用时读取启动进程环境。文件保存路径经过绝对化、规范化和 dataRoot 前缀检查，避免通过文件名写出授权目录。上传大小限制为 20 MB，API 请求使用校验注解，外部模型错误文本会截断。

AgentVersion 不可变，会话固定绑定版本，减少运行中配置漂移。知识库检索按 knowledgeBaseId 隔离，不做全库搜索。向量表初始化使用 `IF NOT EXISTS`，不会在应用启动时删除用户索引。HIGH 工具执行前必须经过参数绑定审批；write_workspace_note 只能在受控目录创建白名单扩展名文件，不能覆盖已有文件。

## 当前局限

生产已升级为 Ollama Qwen 语义 embedding，但无答案题仍可能获得看似合理的最近邻。当前 6 个负例误召回率是 100%，固定阈值无法同时保持高 Recall。系统没有 rerank、BM25、页码和章节级 metadata，文档处理和索引重建目前是同步请求，大文件会占用请求时间。

本地文件、MySQL 和 pgvector 之间没有分布式事务。删除到中间失败时可能出现不一致，目前只会返回明确错误，没有自动补偿和孤儿巡检。知识库没有更新和删除整个库的接口，也没有重复 SHA-256 去重策略。

项目没有登录、RBAC 和多租户，因为定位是个人电脑上的本地工具。它已经有显式 ReAct、RunStep、最小审批、主动取消、总超时和遗留状态关闭，但没有审批人身份、通用策略引擎、MCP、SSH、Coding、独立 AuditEvent、断点续跑和长期记忆。线程中断属于协作式取消，第三方库或不响应中断的工具可能不能立即停止；当前也只支持单后端实例。

## 下一步优先级

EmbeddingGateway、中文语义模型、索引版本、重建流程和离线评测集已经完成。RAG 后续优先处理无答案证据充分性，再以独立实验决定章节切块、BM25 和 rerank，不在当前阶段继续无边界调参。

第二优先级的运行控制已经完成最小闭环：AgentRun 有最大轮数、单工具超时、总运行超时、主动取消、终止步骤和历史详情；重启时能关闭遗留状态。下一步仍需客户端断开联动取消、真正断点续跑、通用 Schema 校验和更多只读工具。

第三优先级的最小安全审批已经完成：HIGH 请求生成参数绑定的 ApprovalRequest，真实拒绝和批准均已人工通过。下一步不是重新做审批，而是补身份、RBAC、策略规则、并发治理，并把相同执行门用于 EXECUTE、PRIVILEGED 类型工具。

SSH 是优先的垂直样例，先在 OpenSSH 测试容器验证只读命令和高风险拦截。Coding 扩展随后增加授权工作区、文件搜索、补丁、构建和测试。两条能力都必须走统一执行网关，不能“先执行后审计”。

## 如何回答“为什么没有一次做完”

因为 Agent 平台的复杂度主要来自状态和副作用。项目先完成无工具的可验证闭环，再用无副作用工具验证版本快照、循环、超时和步骤状态；之后只增加一个受控目录写工具验证审批、拒绝和参数绑定。命令执行与远程能力继续等待身份和更完整的策略门。这种分层扩展让每次新增风险都能被单独验证。
