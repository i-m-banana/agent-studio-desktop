# Agent Studio Desktop 知识包入库说明

这套文档用于 Agent Studio Desktop 的 RAG 手工验收，也用于帮助项目负责人复盘设计、开发、排障和测试过程。建议在前端新建名为“Agent Studio 项目知识库”的知识库，然后逐份上传本目录中的 Markdown 文件。逐份上传比合并成一个大文件更适合验证来源文件展示、跨文档召回和删除一致性。

截至 2026-09-05，知识包已覆盖 MCP 的两种传输：Streamable HTTP 与本机 stdio；还包括 Server 编辑、启停、受保护删除、同步差异、单工具策略、动态发现、稳定命名、Agent 绑定、安全审批和审计。涉及 MCP 时应明确限定为 `2025-06-18` 的 tools 能力，不得扩写为已支持 OAuth、resources、prompts 或全部 MCP 生态。

## 推荐入库顺序

1. 项目总览；
2. 架构与技术选型；
3. 数据模型与版本机制；
4. 模型调用与 SSE；
5. RAG 全链路；
6. 开发时间线；
7. 故障与排查；
8. 测试和验收；
9. 安全、局限与路线图；
10. 面试讲述。

`11-RAG测试题与标准答案.md` 建议先不要入库，把它留在知识库外作为盲测题库。否则问题和标准答案会被直接检索到，只能证明 FAQ 命中，不能验证系统能否从多份项目材料中组合答案。完成一轮盲测后，可以再上传它测试精确问答召回。

`12-推荐Agent系统提示词-不要入库.md` 也不要上传。它是 Agent Builder 的配置材料，应复制到系统提示词输入框，而不是作为被检索的项目事实。

## 事实口径

Agent Studio Desktop 是单机优先、配置驱动的智能体搭建工具。当前已经实现并验证的能力是：模型配置、Agent 草稿、不可变版本发布、普通流式对话、知识库创建、文档上传解析、文本切块、Ollama Qwen 语义向量、版本化 pgvector 检索、索引重建、来源展示、文档删除，以及显式工具运行闭环。工具闭环包含 LOW/READ 的 current_time、HIGH/WRITE 的 write_workspace_note、MCP Streamable HTTP 与 stdio 动态工具、Server 生命周期和工具信任策略、工具版本快照、显式 ReAct、AgentRun/RunStep、执行上限、通用参数 Schema 校验、统一安全执行网关、参数绑定审批、结构化 AuditEvent、主动取消、总运行超时、遗留状态关闭和运行历史详情。384 维词法哈希仍作为离线回退保留，但已不是默认策略。

当前没有实现：登录与 RBAC、MCP OAuth/resources/prompts/sampling/roots/elicitation、stdio OS 级沙箱、SSH、Coding、断点续跑、多智能体、工作流画布、Redis、消息队列和长期记忆。应用重启会把遗留运行标为 INTERRUPTED，而不是从旧步骤继续；高风险审批和 AuditEvent 也还没有审批人身份、签名防篡改、通用策略引擎和远程副作用治理，不能描述成企业级平台。

项目参考过 ai-rag、WaLiSSH 和 WaLiCode 的思路，但新工程在独立 Git 仓库中从骨架开始建设，没有把来源项目整包复制过来。可强调的成果是架构取舍、版本隔离、双数据库边界、RAG 闭环、真实排障和可验证证据，不应把来源项目代码或框架能力描述为个人原创。

## 面试使用原则

理解每个“为什么”比背诵类名更重要。推荐使用“我主导了需求收敛、架构取舍、环境配置、验收和问题闭环，并使用 AI 编程助手加速实现”的真实口径。若面试官继续追问，应能解释数据流、失败场景、替代方案和当前限制，而不是只复述功能列表。
