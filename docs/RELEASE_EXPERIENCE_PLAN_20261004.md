# Agent Studio 发版体验：分批实施计划

日期：2026-10-04。依据 DEV_TO_PROD_RETROSPECTIVE_20261004.md 和 ADR 0032。

## 已确认的起点

时光序本次业务优化已经上线。平台只读接口核实正式发布记录 3179d7e0-27c5-44b7-b3fa-70021ecd561f 为 DEPLOYED，successful=true、exitCode=0；用户人工查看未发现问题。本轮不重放发布，不修改业务网站，不连接生产进行故障演练。

## 第一批：让执行结果能直接看懂

实施结果见 TOOL_RESULT_DELIVERY_20261004.md。

- 统一结果卡展示执行结论、验证范围、影响和下一步，原始回执默认折叠。
- 按结果种类判断成功。兼容没有 task/exitCode 的旧成功预览；MySQL 未验证单独说明。
- 缺退出码、截断或不确定的发布不能显示成功；恢复旧应用与成功上线分开。
- 历史结果只说明当时的事实，不生成旧地址入口，不推断网站现在健康，也不改原回执。

## 第二批：让平台组织一次发版

已实现独立发布工作流与后续批次，交付和新需求验收步骤见 [RELEASE_WORKFLOW_DELIVERY_20261004.md](RELEASE_WORKFLOW_DELIVERY_20261004.md)。单步 release_task 和旧会话仍是原子历史，不推断属于新工作流。

### 日常入口

07 远程工作台选择项目与已发布的部署助手后，使用“准备上线”开始一项独立发布任务。一次只显示一个下一动作及其目的；原子诊断保留在可展开的诊断区。首次接入基线另设流程；已经存在版本 1 基线的网站不重复登记。

准备依次组织候选、镜像、备份、结构、版本历史及线上身份核查。平台选定顺序和材料，LLM 不决定生产阶段顺序。每次原子工具仍经过原审批网关，逐项 HIGH 审批继续有效。“准备上线”不批准后续步骤，“确认上线”先展示风险再请求一次新的发布审批。

### 持久身份与材料

- 新增独立 workflow 聚合及显式阶段成员表；关联项目 ID/配置修订、源码 SHA、目标配置身份、不可变助手版本及工具契约版本。每个调用记录 workflow、阶段、尝试和原 run/step/task 身份。
- 原记录、回执、审批和审计是唯一事实源；聚合只保存关联和执行控制，不提供可由浏览器修改的成功字段。旧发版保持原子历史，不按相邻时间猜测归属。明确选择旧候选时验证项目、源码、目标和摘要。
- 发布参数由后端从同任务的已核实材料生成。客户端只提交任务身份、版本和操作意图，不自行组装八项上线参数。
- 源码、项目权限修订、目标或工具版本变化时，旧计划/批准失效。工具执行前的目录、摘要、目标重验继续保留；不能凭界面绿灯绕过网关。

### 恢复、互斥与失效

- 服务端状态机提供唯一下一动作及具体阻断原因。备份 30 分钟、结构/历史/线上身份 5 分钟仍取原观察时间；指出过期的具体项，只更新该项及依赖它的下游批准，保留已验证候选/镜像。
- 同目标执行租约和阶段幂等键必须覆盖工作流与原子入口；仅禁止同会话重复发送不够。重复点击返回原任务，不创建第二次生产操作。
- 每次推进以任务修订号与操作键原子认领阶段；创建运行、关联成员与锁定目标不能留下可重复派发窗口。先持久认领，再进入一次性审批。
- 刷新只读取任务、运行、材料及待决状态。重启把未确认的执行标为需核查；不续跑、不复用审批、不将执行状态清成可直接重试。
- 拒绝审批显示未执行，后续不自动推进。启动后断线或缺回执显示结果未确认，先安排只读核查；不能只凭进程退出判断生产未改变。
- 失败分阶段保存已经确认的副作用与未知范围。核查完成后只允许从合法阶段创建新尝试，不整条重做、不自动重放迁移/发布。

### 本批必须通过的检查

模拟环境覆盖双击、多标签、相同目标的不同任务竞争、源码/目标/版本变化、证据过期、拒绝审批、执行前后崩溃、缺回执、刷新与重启。验证没有重复生产派发或自动批准。历史已成功发版继续显示当时成功，不误恢复为当前待执行任务。

用户只需检查：打开任务能看见进度与下一步；刷新不改变进度、不触发执行；过期明确说哪项要更新；审批明确项目、目标、动作和影响。无需复制 ID/SHA 或读取 JSON。
