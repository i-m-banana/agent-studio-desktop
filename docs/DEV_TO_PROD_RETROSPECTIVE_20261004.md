## 节省与未节省

节省：逐文件编写实现、部分测试编写与运行、手工选择和传输 JAR、计算摘要、创建与验证备份、输入部署命令、例行健康查询和过程记录。固定工具还减少了误选目标、错用材料、任意命令与凭据泄漏的风险，但一次成功不能量化事故率降低。

尚未充分节省：寻找入口和助手版本、理解各阶段、手动串联与审批、解释 JSON、判断哪些阶段要重做、复制回执来本会话、平台缺能力或出故障时依赖开发者修补。两种负担部分转化为“操作工具”和“协调会话”，不是消失了。

没有同规模人工对照，也没有完整记录人工活跃时间，不能声称省了多少小时或某个百分比。本轮还混入平台开发与排障，不能将整个历时当作正常一次发版耗时。下一次相似 UI 任务应记录人工点选/审批/切换次数、人工活跃时间、工具耗时、重复阶段数及外部帮助次数，分别评估首次接入成本和日常成本。

## 暴露的问题

1. **结果的可信展示不足。** 预览 `successful:true/state:READY` 因缺少退出码被判失败；缺少任务映射导致泛称“固定任务”；原始 JSON 承担了本应由结果卡解释的工作。需保留原始证据，但不能要求普通用户自行解析。会话完成、工具完成、发布完成和当前线上健康是不同状态。
2. **产品把内部步骤交给用户编排。** 原子能力可独立诊断和测试，但日常发布应自动组织。首次数据库基线应是一次性接入步骤，不应与日常 UI 发布混在一起。
3. **跨阶段证据存在，用户仍需手动理解。** 源码、预览、候选、镜像、备份、目标及生产前后身份应归属同一发布任务，刷新只能恢复观察，不能自动续执行或复用审批。新鲜性检查应说明具体哪项过期，不能让用户猜是否整条重做。
4. **正常的拒绝自检容易像故障。** 镜像自检故意使用无效参数，预期拒绝不是实际数据库登记失败；界面应分别显示“入口自检通过”“未连接业务数据库”“完整功能验证未执行”。
5. **失败恢复指导不充分。** 本次平台侧补位处理 SSH 静默超时与有界清理重连；慢速镜像下载并未被 SSH 修复根治。发布 CRLF 故障在第一行退出，修复了模板换行并保留全部安全检查。需要明确失败阶段、已确认副作用、未知范围和下一诊断，而不是一律“失败”或自动重试。
6. **验证能力与界面预期不一致。** 当前网站预览适配 Spring Boot/H2，不是所有项目的通用运行时；MySQL 集成验证仍缺少平台固定执行入口。必须同时展示通过、未运行、失败和不适用，避免把 H2 与 MySQL 覆盖混用。
7. **性能、产物与占用尚不够可解释。** 临时构建器回收可能损失下载缓存，弱网络下重复冷下载。需有明确归属、摘要、限额和回收规则的缓存，以及产物位置、体积、引用与保留原因视图。保留所有备份；不能以过期为由删除，也不能以全局 prune 代替清理设计。
8. **文档混合历史快照与现状。** 部分旧清单仍描述早期“尚未上线”或旧版本的构建方式。复盘须注明日期、当前事实与历史事件，后续应以统一发布任务证据为主，减少多份文档各自维护当前状态。

## 下一轮建议及验收目标

| 优先顺序 | 建议范围 | 可观察的验收目标 |
| --- | --- | --- |
| 1 | 统一工具结果契约和中文结果卡 | 本次历史预览正确显示就绪；未知/截断/缺证据的发布仍不判成功；每张卡解释结果、影响、下一动作 |
| 2 | 同一发布任务下的确定性工作流和唯一下一动作 | 自动传递材料、按顺序执行、检查时效和同目标互斥；刷新不丢进度、不重复执行；失败只核查并从允许的阶段继续 |
| 3 | 工作流授权与生产确认设计 | 单次有限计划绑定源码、目标、步骤、材料及工具版本；真正生产切换仍须清晰确认。现有逐项 HIGH 审批继续有效，不能只改 UI 就静默复用或取消审批 |
| 4 | 阶段化异常诊断及受控缓存/产物管理 | 区分下载慢、SSH 断开、脚本未启动、迁移/切换失败；未知状态不自动重放；只读列出占用及引用，清理需证据与授权，所有备份保留 |
| 5 | 固定隔离 MySQL 集成验证及更完整验收 | 可真实运行三个 *IT 并保留报告；不连接生产或真实卷；验证不支持时明确阻断相关数据库变更，真实故障演练另行授权 |
| 6 | 项目化运行配置 | 将运行时、端口、合成结构/数据和保护范围作为受审配置；同项目改 UI 不重开发平台，新增运行时有明确支持清单及接入测试 |

不建议此时先扩张到所有技术栈，也不建议把多个原子工具简单塞进一个大模型提示词。对用户暴露“准备上线”和“确认上线”等业务入口，内部保留可审计、可测试、可单独诊断的原子能力。

预览/构建可自动化不意味着无风险：本机进程、端口、磁盘和远程候选仍有副作用。一键能力的授权与确定性执行需要一起设计，并针对重复点击、进程重启、证据过期、源码改变、拒绝审批及状态未知测试。

## 下次试验如何判断真正实用

使用另一个同规模、无数据库结构变化的小型 UI 需求。在已支持的项目上，用户只描述需求、确认受控改动、验收预览、确认正式上线和验收网站；不用复制 ID/SHA、写工具名、读 JSON 或在本会话问下一按钮。固定步骤自动进行，必要审批保留，异常可在 Studio 内说明并安全停下。

以这次作为基线比较人工负担，不预设节省比例。若还需要平台开发者陪同才能完成，则流程虽然跑通，仍未达到自助使用目标。
