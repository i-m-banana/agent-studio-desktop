## 一次完整任务

| 顺序 | 点哪里 | 在做什么 | 必须看到的结果 | 失败时怎样处理 |
|---|---|---|---|---|
| 1 | 准备候选 → 审批 | 本地测试、package、上传固定候选文件到新目录 | successful=true、exitCode=0、新 releaseId 和 manifestSha256 | 不能继续；可能留 target 或候选目录，不自动删除 |
| 2 | 构建镜像 → 审批 | 独立构建并非 root 启动自检 | IMAGE_READY、新 imageId、RUNTIME_SMOKE | 不影响运行镜像；可能留构建目录/缓存/镜像 |
| 3 | 创建备份 → 审批 | 备份数据库、uploads、当前部署材料等 | 完整备份 ID、摘要；30分钟内 | 不完整备份不可用；保留全部备份，不自动清理 |
| 4 | 第七步“核查数据库结构” → 审批 | 读取当前结构，包含已经建立的 Flyway 历史 | successful=true、exitCode=0、schemaComplete=true | 停下排查；不复用登记前的旧结构摘要 |
| 5 | 第七步“检查版本历史” → 审批 | 读取数据库版本历史 | 版本1、BASELINE、success=1；不能有失败历史 | 缺失/失败时停止，不修复、删除历史或盲重试 |
| 6 | 第七步“读取当前线上版本” → 审批 | 读取当前 app 镜像、健康与五文件组合指纹 | currentImageId、productionSha256、appHealth=healthy | 停下排查；未健康不允许上线 |
| 7 | 勾选风险说明 → “请求真正上线” → 核对审批 → 批准一次 | 校验八项身份及材料、迁移、app切换、Nginx刷新、健康验证、生产制品同步 | successful=true、exitCode=0、deployed=true、rolledBack=false、manualInterventionRequired=false；currentImageId等于候选imageId | 看下方结果分类，不能只看会话 COMPLETED |
| 8 | 读取当前线上版本、检查站点健康，并打开网站 | 独立后置验收 | 线上imageId等于候选、健康healthy、HTTP200；登录/浏览/详情等原业务正常 | 停止后续发版，保存运行ID及原始回执；不要覆盖数据库 |

结构、历史与线上身份的界面证据有效期5分钟；备份30分钟。执行前服务器仍会重验摘要、备份时效、镜像标签、当前运行镜像、文件指纹、迁移历史及结构。过期重新读取对应项，不必重新登记基线。失败后界面要求读取新的证据；任何高风险重试都需要新审批。

## 如何判断第七步结果

- **已上线且健康验证通过**：上述成功条件全部满足。网站运行候选镜像，生产 `app.jar` / `Dockerfile` 同步为经验证候选；生产 Compose / Nginx / `.env` 保持原样。
- **上线未成功，旧应用已恢复并验证健康**：successful=false、deployed=false、rolledBack=true；currentImageId是前一镜像。恢复也验证容器、首页、只读浏览页及生产文件指纹。兼容数据库扩展仍保留，不能称作“整个系统恢复到逐字节旧状态”。
- **需要人工介入 / 状态未确认**：停止重试。可能是迁移部分完成、Flyway失败历史、镜像恢复失败、凭据清理失败或SSH断开。先读取线上身份、数据库版本历史、站点健康并保存 attemptPath，再针对真实状态处理。禁止盲目 repair、clean、DROP、数据库导入或重放旧审批。

## 副作用与保存位置

新候选在部署根同级 `old-things-releases/<releaseId>/`。发布尝试在其 `publish-<随机ID>/`：保留受保护的前一 app.jar / Dockerfile、迁移/切换/恢复日志及 `receipt.properties`。备份仍位于配置的备份根；镜像与缓存仍在服务器 Docker 数据目录。平台保留 RunStep、ApprovalRequest、AuditEvent。

应用切换及恢复各可能产生短暂访问中断；Nginx刷新不重建MySQL、Nginx或phpMyAdmin。数据库迁移只允许被批准候选中经过审查的版本化扩展SQL：新增可空字段、普通非唯一索引、简单可空字段新表；保留旧结构及约束，并验证新候选实体映射。危险DDL、业务DML、Java迁移、回调、可重复迁移、SQL占位符不走此自动回退流程，应另做数据迁移/收缩审批设计，**不是省略待执行迁移后假报成功**。

不执行 compose down、不删卷、不导入数据库、不覆盖uploads、不全局prune、不删除任何备份或旧候选/镜像。临时数据库凭据只在服务器0700尝试目录内以0600文件传给维护容器stdin，退出时清除；密码和 `.env` 内容不进入回复。源文件测试和target仍在D盘网站目录，Maven/Docker缓存不自动清理。

## 验收范围

本地自动化的模拟Docker事务与隔离MySQL验证不是生产发版证据。真实上线与故障恢复演练须分别留运行ID、原始回执、审批和后置健康证据。第一次可做正常上线验收；不要为了验证回滚而人为破坏生产网站。故障路径先在隔离环境验证，正式故障演练另行批准。
