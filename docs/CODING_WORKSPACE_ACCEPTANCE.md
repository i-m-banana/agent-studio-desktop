# Coding 只读工作区人工验收

适用范围：`feat/coding-workspace` 第一阶段。此清单完成前，只能声明“代码已实现、自动化已通过”，不能声明真实模型与日常环境已验收。

## 准备

1. 选择一个不含真实生产密钥、后端进程有只读权限的本机代码目录。
2. 启动前设置 `AGENT_STUDIO_CODING_WORKSPACE` 为该目录的绝对路径并重启后端。
3. 在目录中准备一个唯一名称的 UTF-8 样例文件，例如 `manual-acceptance/sample-code.txt`，内容至少四行。可另建只含假值的 `.env` 用于拒绝测试，不要使用真实秘密做验收。
4. 记录验收前 `git status --short`，确认后续只读操作没有修改工作区。

## 正向主链

1. 打开 Agent Builder，确认可选择“浏览代码工作区目录”“搜索代码工作区文件”“读取代码工作区文本”，三者均显示 `READ/LOW`。
2. 创建一个只绑定这三个工具的 Agent 并发布版本；发布后修改草稿工具集合，确认旧 AgentVersion 的三个工具快照不变。
3. 在对话中要求列出根目录，再浏览 `manual-acceptance`。应只返回直接子项和相对路径，不出现授权根目录之外的绝对路径。
4. 不指定 `path`，从根目录搜索 `sample-code`。应在 10 秒内一次成功并命中准备的样例文件，结果不应包含 `node_modules`、`target`、`dist` 等默认剪枝目录；再搜索只出现在文件正文、未出现在路径中的词，应不命中，以确认当前是文件路径搜索而不是内容搜索。
5. 读取样例文件第 2 行开始的 2 行。结果应包含正确的行号、总行数、两行内容和 `truncated=true`。
6. 在运行详情确认存在 TOOL_CALL/TOOL_RESULT；安全审计确认存在 TOOL_REQUEST_VALIDATED、TOOL_EXECUTION_STARTED、TOOL_EXECUTION_COMPLETED。AuditEvent 不应包含文件正文，只应包含参数 SHA-256、输出字符数和耗时摘要。

## 负向与边界

1. 请求读取 `../outside.txt` 和工作区外绝对路径，均应被拒绝且不返回外部内容。
2. 请求读取 `.env`，应提示受保护；`.env.example` 可正常读取。
3. 请求读取包含 NUL 的二进制文件、非 UTF-8 文件或超过 1 MiB 的文件，应被拒绝。
4. 若 Windows 允许创建符号链接或目录联接，用工作区内链接指向一个无秘密的外部临时目录；浏览或读取该链接目标必须被拒绝。完成后删除该临时链接和样例目录。
5. 对目录浏览传入超过 200 的数量、对搜索传入超过 100 的数量、对读取传入超过 500 行，均应被参数边界拒绝。
6. 再次检查 `git status --short`，除人工创建的验收样例外不应出现 Coding 工具造成的文件修改；运行中不应生成 ApprovalRequest，因为本阶段没有写操作。
