## 2026-09-30：镜像构建成功不等于非 root 维护入口可启动

受审基线登记的真实失败返回 `PropertiesLauncher ClassNotFoundException`；随后用户运行只读 `DATABASE_BASELINE_STATUS`，目标库报告无 `flyway_schema_history` 表。原始候选 JAR 含该启动类，故重点转向镜像内可读权限：隔离构建在 `umask 077` 下复制 JAR，所得构建上下文副本可能为 root 独读，Dockerfile 的 `COPY` 将其放进非 root 运行镜像。旧构建只核对镜像标签与摘要，没有真正以非 root 用户启动入口，因而把不可用于基线任务的镜像误判为就绪。

修复不弱化权限边界：候选原件仍为私有，只对已核对哈希的独占上下文副本设为 0644；构建后以无网络、只读、非 root、资源限额容器执行固定维护入口，并故意给无效摘要，要求在接触凭据/数据库前返回受控 `IllegalArgumentException`。若类不可读、超时或回执不符，失败停在 `RUNTIME_SMOKE`，不发镜像成功回执。旧成功镜像不会自动变更，下一次须由用户审批重构建并取得新 imageId。新旧镜像、候选与生产服务均不做全局清理。本项真实新镜像与数据库登记尚待用户验收。

## 尚未解决、不得隐去的事项

- 基础镜像和构建器镜像仍使用浮动标签；构建产物镜像 ID 已固定，但不能据此宣称整个构建可重复。
- 专用构建器有资源限制；Docker daemon 下载和镜像导入不保证受完全相同限额约束。
- 断网或主机故障可能留下构建器、候选、镜像和尝试日志；不执行全局 prune，不自动删除历史产物。
- 历史会话和成功候选选择入口已列入计划，按用户要求待发版链路完成后开发。
- 数据库采用自动更新结构会破坏应用镜像回滚的可靠性；发布阶段不能把“镜像切回”当成“业务恢复”。

## 后续开发原则

保留完整的测试、制品暂存、镜像构建、备份、发布、健康验证、失败补偿能力，增加可靠性与证据，不用取消功能代替修复。新行为仍必须通过固定业务工具、AgentVersion、SafeExecutionGateway、参数绑定的一次性 ApprovalRequest、RunStep 和 AuditEvent。

正式发布前需独立批准网站数据库迁移改造：以现有数据库结构建立基线，版本化迁移、启动时校验，支持兼容的结构演进，并验证旧应用回滚后可读写。不在普通失败回滚中自动覆盖生产数据库；破坏性迁移需要单独审阅与授权。真实生产切换和故障演练仍须独立人工审批及验收，不能由本阶段成功替代。
