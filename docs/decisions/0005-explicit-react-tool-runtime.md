# ADR 0005：显式 ReAct 工具运行时

## 状态

已采用，第一阶段于 2026-09-04 实现。

## 背景

模型能够生成工具调用，并不代表模型可以直接执行本机副作用。平台需要在模型决策和实际执行之间建立可校验、可限制、可观测的边界，同时保证已发布 Agent 的行为不会随草稿修改而漂移。

## 决策

- 工具由平台 `ToolRegistry` 注册，模型只收到当前 AgentVersion 已绑定工具的描述。
- 草稿保存工具绑定；发布时把工具名快照到 `agent_version_tool`，历史版本保持不变。
- 运行时采用显式循环：模型返回 tool call，平台校验是否绑定、解析参数、执行工具，把 Observation 写回消息，再请求模型生成下一步。
- 第一阶段只开放 `current_time`，风险等级为 LOW、操作类型为 READ，参数只允许可选 IANA `zoneId`。
- 每次对话创建 `AgentRun`，模型调用、工具请求和工具结果写入 `RunStep`；SSE 发送 `run`、`step`、可选 `sources`、`delta`、`done` 或 `error`。
- 默认最多 4 个工具轮次、每轮最多 4 个调用；每个工具有独立超时。达到限制后运行失败并安全停止。
- 工具异常作为失败 Observation 返回模型，使模型有机会解释失败；越权工具请求和运行上限错误直接终止运行。

## 取舍

显式循环比让 SDK 自动执行工具多一些代码，但执行边界、审计数据和失败语义都由平台掌握。工具版对话目前使用非流式模型调用完成每轮决策，因此最终答案以单个 `delta` 返回；无工具路径仍保持真正的 token 流式输出。

## 未包含

本阶段没有实现通用 JSON Schema 校验、高风险审批、MCP、SSH、Coding、运行取消、总运行超时、崩溃恢复和补偿执行。新增具有写入或执行副作用的工具之前，必须先完成审批和参数绑定机制。
