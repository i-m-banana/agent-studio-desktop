# ADR 0016：摘要绑定的受审 Coding 文本补丁

## 背景

Coding 只读第一阶段已经能够定位并读取文件，但不能形成最小的“读取—修改—审计”闭环。直接开放任意覆盖、模糊 diff 或命令执行会同时引入路径逃逸、并发覆盖、补丁错位和未经确认的副作用，超出当前阶段的风险承受范围。

## 决策

新增内置工具 `apply_workspace_text_patch`，标记为 `WRITE/HIGH`。它与三个只读 Coding 工具共享 `CodingWorkspace` 路径边界，并继续由 ToolRegistry 注册、AgentVersion 快照绑定、SafeExecutionGateway 执行。每次调用必须形成参数绑定的一次性 ApprovalRequest；没有批准、拒绝、过期或运行取消时不会执行写入。

`read_workspace_text_file` 在原有分段内容外返回完整原始字节的 SHA-256 和字节数。写工具要求模型提交相对路径、该 SHA-256，以及 1–10 个按顺序执行的 `{oldText,newText}` 精确替换。每个 `oldText` 在当时内容中必须恰好出现一次；摘要过期、文本缺失或多处匹配都会拒绝，避免静默错改。补丁参数文本合计最多 12000 字符，输入和结果文件均不超过 1 MiB，仍只接受严格 UTF-8 且拒绝 NUL 二进制文件。

写入仅针对已经存在且可写的普通文件，不创建、删除或重命名文件。工具先在目标同目录写临时文件，提交前再次校验目标摘要，再使用同文件系统原子替换；文件系统不支持原子替换时安全失败，不退化为非原子覆盖。结果只返回相对路径、前后摘要、替换数量和字节数。

## 结果与边界

该设计提供轻量、可审批、可检测陈旧版本的文本修改能力，不引入新的数据库表、文件 REST API、MCP Server 或旁路执行器。RunStep 保留模型可见参数和结果，AuditEvent 继续只保存参数摘要与执行概况，不复制代码内容。

本阶段不包含统一 diff 解析、模糊上下文匹配、补丁预览专页、撤销历史、新建/删除/重命名文件、批量跨文件事务、Git 操作、命令执行、构建测试、OS 沙箱、SSH/SFTP 或部署。自动化通过不等于真实模型人工验收通过。
