# ADR 0003：本地 RAG 基线

- 状态：已接受
- 日期：2026-09-02

## 数据边界

知识库及文档元数据保存在 MySQL，原始文件保存在本机 `data/knowledge`，文档片段与向量保存在 PostgreSQL + pgvector。业务仓储显式绑定 MySQL，向量仓储显式绑定 PostgreSQL，避免多数据源自动装配时选错连接。

Agent 草稿可以选择知识库；发布时只把知识库标识写入不可变 `AgentVersion`。对话检索始终使用会话绑定版本中的知识库，不读取后来修改的草稿。

## 解析和检索

上传文件最大 20 MB。Apache Tika 负责提取 TXT、Markdown、PDF、DOCX 等常见文档文本，随后进行清洗、重叠切块、向量化并写入 pgvector。检索使用余弦距离，命中片段既注入模型上下文，也通过 SSE `sources` 事件返回前端。

当前使用内置 384 维词法哈希向量：对规范化词项和字符二元组做有符号哈希并归一化。该方案离线、可复现，不要求用户额外提供 embedding 服务，目标是先跑通存储与检索契约。它不等价于语义 embedding，跨语言或同义改写召回能力有限；后续应通过统一 embedding 网关替换，并以新索引版本重建向量。

## 删除语义

删除文档时依次清理 pgvector chunk、MySQL 文档元数据和本地文件。由于三个存储之间没有分布式事务，清理失败会明确返回错误；后续阶段可增加补偿任务和孤儿数据巡检。
