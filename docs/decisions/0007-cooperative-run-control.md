# ADR 0007：协作式运行取消与截止时间

## 状态

已采用，2026-09-05 实现。

## 决策

- 每个 AgentRun 在执行线程启动时注册到 `RunControlService`，默认总时限 120 秒。
- 用户通过 `POST /api/runs/{id}/cancel` 提交取消，数据库先进入 `CANCEL_REQUESTED`，控制器再中断对应执行线程。
- 截止时间由独立调度器触发，最终状态为 `TIMED_OUT`；用户取消最终状态为 `CANCELLED`。
- ChatService 在检索、模型、审批、工具和持久化边界检查终止信号；工具异常处理不得吞掉取消信号。
- 最终状态使用带前置状态条件的原子更新：普通完成/失败不得覆盖 `CANCEL_REQUESTED`，终止收口才能把非终态更新为 `CANCELLED`、`TIMED_OUT` 或 `INTERRUPTED`。
- 终止写入 `RUN_TERMINATION` 步骤并发送 `terminated` SSE。部分流式文本不会保存为完整 assistant 消息。
- 启动时把上一进程遗留的非终态运行关闭为 `INTERRUPTED`，待决审批改为 `EXPIRED`，避免数据库长期显示仍在运行。
- 提供最近运行摘要和单次完整步骤 API，前端增加运行记录页。

## 取舍与边界

Java 线程中断是协作式取消，不保证任意第三方库立即停止；平台必须在边界显式检查信号，工具也应响应中断。当前“重启恢复”只表示识别并关闭遗留状态，不会从 RunStep 断点续跑。产品按单实例运行设计；多个后端实例共享同一数据库时，启动清理会误判其他实例的活动运行，因此多实例部署前必须增加实例租约或心跳。
