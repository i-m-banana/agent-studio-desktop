# ADR 0027：网站版本化数据库迁移与兼容发布前置

## 状态

用户于 2026-09-28 明确授权修改本地 D:/idea_work/shiguangxv，表示已自行备份副本。已实施本地迁移基础设施与测试；真实生产结构核对、登记基线、发布和故障回滚仍需独立授权及验收。网站目录本身不是 Git 仓库，本轮不初始化 Git、不改用户备份。

## 决策

保留网站所有业务能力，不以“永久不允许数据库结构变化”规避回滚问题。引入 Spring Boot 3.2.5 管理的 Flyway 9.22.3 和 MySQL 支持，Hibernate 从 update 改为 validate，迁移校验和有界历史确保结构变化可追踪。关闭自动 baseline、clean 和乱序迁移；非空、无历史的库明确拒绝接管。

当前源码派生的 V1 仅初始化空库，不宣称等于生产结构。旧快照仍有已删除的表/列，因此不导入旧 SQL 或数据目录建立所谓生产基线。生产首次接管需要先备份、核对当前结构、隔离验证，再单独审批登记基线，不修改业务表和现有数据。只读 CurrentSchemaVerifier 检查表/列集合及 Hibernate 映射类型，但不替代索引/约束/真实数据业务验证。

数据库演进采用 expand/contract，兼容扩展后验证旧版读写；应用回滚保留已经执行的兼容结构，不自动倒放 DDL 或覆盖生产数据库。破坏性或不兼容迁移需要额外审阅和独立恢复方案，Flyway 的存在本身不等于任意版本都能安全回滚。

## 自动化与保留能力

原有页面、权限、投稿晋升、标签、收藏和评论测试保留，改用迁移建表与 Hibernate validate。H2/MySQL 枚举表示不同，分别提供迁移脚本，自动化保证其他 SQL 相同。测试包括空库、重复启动、非空库拒绝、明确 baseline 后保留行、迁移校验和漂移拒绝、旧结构拒绝及添加可空字段后旧版读写。独立 MySQL 8.0 Testcontainers 套件复用原功能测试；测试客户端升级至 1.21.4 兼容本机 Docker 29，不降级服务器或跳过测试。

本轮不改 AgentVersion、Gateway、ApprovalRequest、RunStep、AuditEvent、RAG/MCP 执行基线，不暴露新的任意迁移 SQL/命令接口，不连接生产数据库。网站是 Thymeleaf 应用，生产产物由 Maven 打包；之前已经成功构建的旧候选不会随源码改变，必须重新准备候选并构建。

## 后续

在生产结构核对与接管维护完成后，继续实现确定镜像、新备份、受控 app 切换、健康验证与失败补偿。仍需固定业务工具和一次性 HIGH 审批，不以本地仓库写权限代替生产授权。完整网站操作与验证说明见 D:/idea_work/shiguangxv/docs/DATABASE_MIGRATION.md。
