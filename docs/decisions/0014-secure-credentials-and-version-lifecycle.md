# ADR 0014：安全凭据与 Agent 版本生命周期

## 决策

桌面端允许用户在前端输入模型和 MCP 所引用的密钥，但前端只承担输入与状态展示。后端使用 Windows DPAPI 将密钥加密为当前 Windows 用户绑定的密文，保存在本地 `data/secrets`。MySQL、AgentVersion、MCP 配置、日志和 API 响应仍只出现凭据名称，不出现值。

运行时凭据解析顺序固定为：进程环境变量优先，其次 DPAPI 安全存储，最后为未配置。这样本地用户保存一次后不必每次启动重新输入，部署和临时调试又可以用环境变量显式覆盖。页面只展示“环境变量 / 安全存储 / 未配置”，更新采用新值覆盖，任何接口都不支持读取明文。环境变量来自父进程，页面不能替用户删除，因此处于覆盖状态时禁用删除并给出说明。

AgentVersion 仍保持内容不可变，但新增独立的归档状态。对话测试台默认仅展示每个 Agent 的最新未归档版本，用户主动勾选后才显示未归档的历史版本。归档只影响新会话选择，不影响按版本 ID 读取的历史会话和运行审计。

永久删除需要同时满足：不是 Agent 最新版本、已经归档、Conversation 与 AgentRun 引用数均为零。存在引用时只允许归档；最新版必须先发布替代版本。删除时仅清除版本工具绑定和版本快照，不触碰历史数据。

## 原因

把密钥放入 localStorage 或明文数据库会让浏览器脚本、备份和普通查询轻易接触秘密；完全依赖环境变量又不符合桌面产品的日常使用习惯。DPAPI 让密文只能由同一 Windows 用户解密，适合当前单机 Windows 边界。

历史版本直接硬删除会破坏 AgentRun 可复现性和外键完整性；完全不提供整理能力又会污染版本下拉框。归档和严格受限删除将“日常可用性”与“运行审计不可破坏”分开处理。

## 边界

DPAPI 文件不是跨电脑、跨 Windows 用户的可迁移凭据备份；迁移数据时应在新环境重新输入密钥。当前实现也不是多人租户密钥保险箱。归档不是内容修改，恢复后原版本快照仍保持不变。
