# ADR 0013：工具预算收尾与审批可见性

## 背景

真实 Tavily MCP 测试连续暴露两个问题。其一，第二次审批出现在可滚动消息区顶部，用户停留在底部时不易发现；审批等待 90 秒后过期，而总运行仍受 120 秒限制。其二，模型为核对相互冲突的新旧规范连续搜索和提取，第四轮已取得官方证据，但循环代码在执行完最后一批工具后直接抛出“达到最大工具轮数”，没有给模型总结机会。工具输出还同时受运行记录的 4000 字符限制，多来源搜索结果过早截断会增加补充查询。

## 决策

- 审批卡在对话滚动容器内固定可见，显示秒级倒计时，并用浏览器标题提示；过期后禁止提交失效决定。
- 最大轮数继续代表安全工具预算，不简单增大。最后一轮工具执行完后，平台以空工具列表发起一次最终模型调用，明确要求只依据已有观察回答。
- 最终调用记录为 `MODEL_FINALIZATION`，原因写为 `MAX_TOOL_ROUNDS`；若模型在没有工具定义时仍请求工具或不返回正文，运行才失败。
- 运行记录和审计展示仍截断到 4000 字符；传给模型的工具观察独立放宽到 16000 字符，并显式标记截断，兼顾可解释记录、上下文成本和多来源完整性。
- 不在通用运行器中按工具名硬编码 Tavily，也不禁止所有相同参数调用，因为时间、状态查询等工具可能合法重复；通过最少调用提示、预算和最终收尾共同约束。

## 结果

审批仍保持逐次、参数绑定和一次性消费的安全语义，但后续审批不再因滚动位置被隐藏。多轮检索即使耗尽工具预算，也会利用已经付费取得的结果形成答案，而不是整次失败。系统没有以无限加轮数掩盖模型策略问题，因此仍能控制费用和循环风险。
