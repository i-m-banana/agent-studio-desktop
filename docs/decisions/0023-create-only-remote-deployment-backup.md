# ADR 0023：只新增的远程发布前备份

## 状态

已接受；自动化验证及真实生产服务器两次创建型备份人工验收通过。

## 背景

只读部署诊断已经确认生产目标、固定服务和当前发布指纹，但任何后续制品上传或发布都必须先有可核验备份。向模型开放路径、备份名、数据库参数或 Shell 会破坏既有固定任务和一次性审批边界；自动清理旧备份也可能直接消灭恢复点。

## 决策

新增 `prepare_remote_deployment_backup`，标记为 `SSH/WRITE/HIGH`，Schema 是不接受任何字段的空对象。工具复用现有 SSH 身份、密码凭据、固定 SHA-256 主机指纹和 V12 部署 Profile，并把完整生产目标与 `BACKUP:CREATE_ONLY` 绑定到一次性 ApprovalRequest；批准后仍由 SafeExecutionGateway 复核目标。

服务器生成 UTC 时间戳加随机后缀的 backupId，并用 `mkdir` 独占创建新目录。工具没有覆盖、删除、清理、恢复或自定义名称分支。固定流程备份 MySQL `--single-transaction` 逻辑导出、`data/uploads` 压缩包、app.jar、Dockerfile、Compose、Nginx 配置、`.env`、镜像清单和四个固定服务状态。数据库凭据只在 mysql 容器内部从环境变量解析；`.env` 以 0600 权限复制且不读取、不回传。

所有九个负载文件写入 SHA256SUMS；manifest 记录 backupId、时间、固定目标和文件清单，并生成独立 SHA-256。数据库导出和 uploads 压缩包必须非空，镜像及服务清单必须存在，成功回执必须包含严格格式的 backupId、路径、manifest 摘要、大小和文件数。失败时保留已创建目录并写入 `FAILED`，不自动删除现场。

## 后果

- 当前只有“创建并验证新备份”，没有备份浏览、下载、清理、还原或自动恢复；
- 固定命令会读取生产数据库和文件并占用服务器磁盘，必须逐次 HIGH 审批；
- 120 秒内部时限或中断会关闭 Exec Channel，但远程失败目录仍需人工核查；
- 自动化通过不代表真实备份可恢复，后续人工验收必须核对远程目录、权限、摘要和非空文件；
- 在恢复演练完成前，不得声称已经具备生产数据库恢复能力。
