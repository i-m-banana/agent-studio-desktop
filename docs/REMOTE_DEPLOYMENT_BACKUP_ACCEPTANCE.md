# 远程发布前备份人工验收

## 当前口径

固定创建型备份工具、工作台入口、自动化测试和真实生产服务器正向验收均已完成。两次执行生成不同的独占目录，第二次由工具在成功返回前自动校验两份摘要清单；可以写“创建型备份已人工验收”，但不能写“可以恢复生产”，恢复仍需独立演练。

## 执行前

1. 确认部署 Profile 为 READY，备份根是独立普通目录且磁盘空间充足；
2. 发布一个包含“创建受控远程发布前备份”（`prepare_remote_deployment_backup`）的新 AgentVersion；
3. 确认工具卡为 `SSH/WRITE/HIGH`，Schema 没有 path、name、command、参数、环境变量、覆盖或恢复字段；
4. 记录备份根执行前目录列表，不打开 `.env`。

## 正向验收

1. 在“远程工作台 → 部署”点击“请求创建备份”，核对审批目标包含 SSH 身份/指纹、部署根、Compose 与健康目标，以及 `BACKUP:CREATE_ONLY`；
2. 批准一次，确认返回全新 backupId、固定备份根内路径、数据库及 uploads 非零大小、九个负载文件和 manifest SHA-256；
3. 通过服务器人工只读检查确认新目录权限、`.env` 权限 0600、database.sql 和 uploads.tar.gz 非空；
4. 在备份目录运行只读摘要校验，确认 SHA256SUMS 全部通过，manifest.sha256 通过；
5. 再执行一次，确认生成不同目录，第一次备份未被修改或删除。

## 负向验收

1. 拒绝审批，确认没有创建目录；
2. 尝试让模型指定路径、名称、命令、数据库参数、删除或恢复选项，确认在执行前被拒绝；
3. 审批等待期间修改部署 Profile，确认旧审批因目标变化失效；
4. 自动化已覆盖非零退出、超时关闭和危险参数；真实服务器不主动破坏生产数据库制造失败；
5. 确认所有页面、RunStep 和 AuditEvent 都没有 `.env` 内容、数据库密码或 Token。
