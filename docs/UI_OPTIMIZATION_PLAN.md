# Agent Studio UI 优化计划

计划日期：2026-10-02。

起点：已验收的稳定版本 `main / fb651e8`。问题依据：[全站UI审查报告](UI_AUDIT_2026-10-02.md)。

顺序：**先做减法，再做界面美化，最后增加功能。** 按用户后续安排，第一、二轮一起完成后统一查看。第一、二轮已通过用户验收，获准提交并进入第三轮。实施结果见 [本轮完成记录](UI_OPTIMIZATION_ROUNDS_1_2.md)。40项审查中划归第三轮的能力仍保留在后续计划中。

## 优化后的使用目标

日常使用时，用户先看到要处理的内容和可用操作。配置时，只填写当前需要的项目。排查时，再打开运行、参数和审计详情。

保留当前暗色风格和八个模块作为第一轮起点，不先更换整套导航或引入新的概念。已验收的紧凑历史入口、可恢复删除和浮动通知继续保留。

“做减法”是减少默认展示、重复操作和占位入口，不是删除后台能力或历史数据。工具限制、一次性审批、风险说明、真实状态、历史证据和恢复规则均保留。

## 第一轮：做减法——让已有功能更容易使用

### 按这个顺序实施

| 批次 | 具体改动 | 保留的内容 | 用户怎么验收 |
|---|---|---|---|
| 1A：聊天与助手管理 | 聊天默认显示消息；原始运行步骤、旧审批事件和技术参数收进详情。助手页默认显示助手列表，创建/编辑时才展开表单；工具详细说明收起，卡片上的内部工具名改为简短能力摘要。 | 正在等待的审批保持醒目；运行进度仍可见；完整工具边界与记录仍可查看；草稿与已发布版本仍分开。 | 打开旧会话先看到聊天；找一个助手不必翻过创建表单；编辑时仍能找到原来的字段与工具。 |
| 1B：模型、知识库与MCP | 模型页中的服务器设置独立分区、默认收起；已配置场景不再被新建表单占据大半屏。知识库和MCP先显示已有资料/连接；新建表单按需打开。长帮助改为旁边的简短说明和可展开详情。 | 模型、SSH、凭据和MCP配置不删除、不自动改变。服务器指纹核对及风险降低确认保留。 | 不新增配置时，可以直接查看当前模型、文档和连接；原配置功能仍能找到。 |
| 1C：远程工作台 | 部署页区分首次配置与日常发布；已完成的首次设置收起，默认突出本次缺少什么和下一步。重复检查入口合并，但后台校验不减少。“变更”占位标签退出常用标签栏，真实变更预览留到第三轮。概览收起内部类名和无助于操作的数字展示。 | 每次发布仍需新的必要证据与审批；备份有效期不放宽；高级诊断、原结果、首次配置及原工具仍能查看。 | 已登记的网站不再先看到整套首次登记教学；能说清下一步该做什么；不会点进只有“以后会做”说明的主入口。 |
| 1D：记录和状态收口 | 运行详情先显示结论与关键错误，步骤和审计收起。统一区分“已结束/操作成功”“历史结果/当前核查”“已配置/已测试”。缩短面向用户的技术文案，修正过期说明和错误入口指向。 | 不改写原始状态、回执和审计；不凭历史记录推断当前线上状态；不自动测试生产目标。 | 能看懂任务结果，历史记录带时间和来源，不会把旧WAITING当成现在等待审批。 |

### 这一轮明确不新增

不新增搜索、复制、导出、模型测试、完整Diff、助手模板、批量上传、仪表盘或新的自动执行功能。不为了隐藏信息再造一个复杂管理中心。

现有交互中的明显错误随相关页面修正，例如入口指错页面、中文输入法确认文字可能误发送、观察原任务时缺少已有取消操作入口。这些属于修复既有行为，不能借此扩大功能范围。审批不会因刷新重新提供执行授权。

### 第一轮通过标准

1. 在“对话测试台”打开旧会话，首先看到聊天内容，技术步骤可以主动展开。
2. 在助手、模型、知识库和MCP页面，不创建新项目也能直接浏览已有内容。
3. 在部署页能指出本次下一步；不需要读完首次配置教学或内部参数。
4. 现有历史恢复、删除/恢复、发送、取消及审批规则没有退化；浮动通知仍不挤压页面。
5. 默认界面的说明、重复结果和占位内容明显减少，没有新增一组必须理解的面板。

## 第二轮：界面美化——把整理后的结构做清楚

以第一轮已验收的结构为基础，不再顺手改功能流程。

| 内容 | 具体处理 | 用户怎么验收 |
|---|---|---|
| 页面空间 | 缩小巨型页头和不必要留白；调整导航宽度，让内容成为主角。 | 常用操作能在正常窗口中看到，不靠缩放找按钮。 |
| 文字层级 | 提高正文与主要操作的可读性；统一标题、说明、辅助文字，技术标识不再抢眼。 | 正常缩放即可读清，知道哪些是主要信息、哪些是辅助说明。 |
| 控件和颜色 | 统一输入框、按钮、列表、弹窗、折叠详情和提示；主要、次要、危险操作层级一致。状态同时用文字说明，不能只靠颜色。 | 不同页面的同类操作长得一致；删除和执行不会与普通浏览混淆。 |
| 工作台布局 | 修复桌面溢出；提供收起侧栏的布局控制；窄屏改为可直接到达的文件/任务/助手区域。 | 常用桌面宽度不裁掉按钮；窄屏不用滚动数千像素找发送框。 |
| 焦点与反馈 | 清晰显示当前选择、键盘焦点、正在处理的对象和禁用原因；重要失败信息能在原操作旁找到。 | 点击后知道正在处理什么；不能点击时知道原因。 |

第二轮不做新仪表盘、装饰图表、动画背景或成套换主题。截图好看不能替代真实操作可用。

验收覆盖1440px与1280px桌面宽度、390px窄屏和放大显示。页面测试会使用独立浏览状态，避免改变用户正在填写的内容。

## 第三轮：功能新增——先补常用缺口

第三轮也分批交付。前一批稳定后再进入下一批，不将所有建议同时加入界面。

| 批次 | 新增能力 | 交付范围与边界 | 用户怎么验收 |
|---|---|---|---|
| 3A：找得到、取用方便 | 会话/助手/文档搜索与筛选；消息和代码复制；定位最新消息；旧运行分页；文档与长文件阅读。 | 列表按实际需要增加功能，不在每行铺满按钮。导出由用户主动选择，不自动上传资料。 | 能快速找到一段聊天、一份文件或一次任务；能复制内容、查看较早记录和长文件剩余部分。 |
| 3B：配置和资料能维护 | 模型编辑；模型/助手归档与引用保护；助手复制；知识库名称/说明编辑；MCP导入时明确选择目标知识库。 | 已有更新接口优先接入。需要后端的新管理操作单独实现；不改变既有版本快照，不自动删除被引用对象。 | 填错配置能修改；清单能整理；导入前知道资料进入哪个知识库。 |
| 3C：连接与处理进度可理解 | 用户主动连接测试；上传/解析阶段与失败重试；MCP参数完整表单、Prompt复制/填入；设置保存反馈；按受影响功能展示诊断。 | 测试说明是否会访问外部服务或产生模型调用。重试由用户主动发起；配置保存只保存最终有效值。 | 能知道连接是否测通、文件处理到哪一步；失败后知道如何处理。 |
| 3D：复杂任务能在执行前看懂 | 真实文本变更预览与审批摘要；助手版本变化对比；历史回答来源恢复；会话、任务和原始记录相互跳转。 | 必须使用真实参数、原文件及持久化证据，不伪造Diff或历史来源。任何高风险执行仍保留一次性审批和后端重验。 | 批准前看懂对象、变化和影响；回看结果能找到当时的依据。 |

不将“一键自动上线”、自动清理备份、自动重试生产操作或永久清空审计列入本次UI优化。它们会改变操作能力与风险边界，需要独立需求和验证。

## 每轮怎么交付

1. 从稳定main建立专门开发分支，避免直接在稳定版大规模改UI。计划阶段不创建分支。
2. 按批次制作可运行的界面，保持页面入口与已有数据兼容，不用不可点击的草图代替交付。
3. 检查现有前端测试、构建和真实页面；涉及后端与数据库时，增加相应验证。纯样式调整不重复运行无关后端检查。
4. 给用户一张短验收单：每步仅写“做什么、应该看到什么”。开发侧负责核对编号、接口、审计和原始证据。
5. 用户通过该轮后，再记录验收并提交。整轮达到稳定状态后合并、推送，遵循届时的授权范围。

不替用户清理历史，不修改manual-acceptance/与使用问题.txt，不执行生产发布或故障演练。遇到需要真实高风险操作才能验证的部分，先完成可复现的本地/隔离验证，不用日常UI验收诱导用户重新上线。

## 当前下一步

**进入第三轮3A：找得到、取用方便。** 先完成搜索、筛选、复制与阅读能力；3B–3D继续按批次推进。

这一轮的成功标准是“比以前少看、少找、少绕路”，而不是“多了一套管理功能”。
