# Agent Studio 全站 UI 审查

日期：2026-10-02。审查基线：`main / fb651e8`。

## 先看结论

当前界面更像把开发阶段的验证能力逐项摆出来，尚未充分围绕日常使用组织。主要问题是：常用操作缺入口，技术记录抢占主视图，不同页面的状态含义不一致，以及用户要在多个页面之间记住上下文。

优化重点应该是让用户更容易完成事情，而不是加更多面板。后台工具、审批、证据保留都有价值；需要调整的是默认展示层级和操作路径。

本轮整理出 **40 项问题或改进项**。这不是40个已经复现的程序错误：下文分别标记页面与代码确认的现状、代码显示的交互风险、设计改进建议。

## 审查范围与证据

已观察全部8个页面：模型、知识库、MCP、助手管理、聊天、远程工作台、运行记录、系统诊断。远程工作台的概览、文件、变更、任务、部署、输出6个标签也已逐一观察。

结合 App.tsx、HistoryPanel.tsx、MarkdownMessage.tsx、样式及相关后端接口，检查入口、列表、状态、表单、反馈、恢复、任务上下文和布局。保存了页面快照与截图，另核查1440×900和390×844布局；默认桌面视口也有实际溢出记录。

本轮没有发送聊天、执行测试/构建/上线工具、修改配置、删除记录或改变生产网站。进入远程工作台时，原页面自动通过受限SFTP只读加载目录；进入系统诊断时，原功能读取本机就绪状态。没有为了测试失败状态制造故障。

优先级：**先做**表示阻碍常用流程、容易误解结果或存在操作风险；**随后**表示提升管理效率；**后续**表示完善辅助体验。优先级是本轮设计判断，不代表安全漏洞等级。

证据标记：**实**＝页面及代码确认；**码**＝代码确认，相关特殊条件未现场触发；**建**＝基于现状提出的设计建议。

| D02 | 随后/实 | 模型密钥READY只表示凭据存在；MCP READY依据上次同步记录，不是重新连接验证。标题、颜色缺少这一层区分。 | 明确“凭据已配置”“上次同步成功”和“本次连通测试”，显示测试时间与范围。 | 用户不把保存过密钥或过去同步成功当成现在实际可调用。 |

## 最值得先做的具体事项

建议第一轮只解决下面这些用户能直接感受到的问题，而不是重做全部设计：

1. **聊天先显示聊天。** 把原始运行与历史审批收进详情；补停止、中文输入法处理和最新消息定位。对应H01、H03、H04、H05。
2. **模型能维护。** 接上已有编辑接口，把模型与其凭据放在同一操作路径，明确测试入口。对应M01、M03。
3. **助手列表先显示助手。** 收起巨型创建表单；工具分组搜索，不把内部工具名铺满卡片。对应A01、A02。
4. **工作台先解决空间和下一步。** 消除溢出，支持收起左右栏；部署区区分首次配置和日常发布，去掉无用占位主入口。对应R01、R02、R03。
5. **状态不误导。** 区分结束与成功、历史与当前、配置与验证、局部失败与整个平台离线。对应G04、L02、R07、D01、D02。

复制、搜索、排序、分页与预览属于高频管理能力，安排第二轮集中补齐。完整Diff、历史检索来源、连接归档和诊断分级需要后端或数据支持，不宜作为“改几个样式”顺带完成。

## 实施顺序与验收方式

| 阶段 | 交付 | 用户只需检查 |
|---|---|---|
| 第一轮：少堆叠、常用入口可见 | 聊天/助手/模型默认布局、工作台空间、准确状态和输入/停止操作 | 能否很快找到常用操作；聊天是否先显示消息；下一步是否明白。 |
| 第二轮：资料和记录好管理 | 搜索筛选、复制、预览、分页、模型/助手整理、明确导入目标 | 能否找到、修改、整理和取用已有资料。 |
| 第三轮：复杂任务能看懂 | 真实变更预览、任务与审批摘要、版本变化、诊断影响范围 | 执行前知道目标和影响，失败后知道下一步。 |

每轮只做一组完整流程，用“操作 → 应看到的现象”验收。保留已验收的历史恢复、可恢复删除、浮动通知；不以减少UI为由删除安全限制、审批、证据或后台能力。避免新占位标签和永远展开的说明板。
