## 如何判断成功

- 操作助手的中文“执行成功”必须对应原始回执 `successful=true`、`exitCode=0`，并满足本步骤特有的成功字段。
- 结构核查回执的 `baselineRegistered=false` 表示本次只读工具没有执行登记，并不表示结构核查失败；第 4 步主要核对 `schemaComplete=true`、结构摘要和输出未截断。只有第 5 步登记任务才要求 `baselineRegistered=true`。
- 运行或 TOOL_RESULT 的 `COMPLETED` 表示执行已结束，不能单独证明检查通过。非零退出结果也会被完整记录为一次已完成的工具调用。
- 没有 TOOL_RESULT、只有模型文字，不算执行证据。拒绝审批或审批过期，也不算执行成功。
- 右侧“技术详情与原始 JSON”可以展开核对；左侧“运行记录”保留运行 ID、工具回执、审批和审计。刷新页面会恢复近期工具结果；过期备份仍保留，但不能用于本次登记。

### 第 5 步审批时核对六项身份

“查看本次六项绑定证据”会自动汇总：

| 字段 | 中文含义 | 来自哪一步 |
| --- | --- | --- |
| releaseId | 候选编号 | 第 1、2 步 |
| manifestSha256 | 候选文件清单摘要 | 第 1、2 步 |
| imageId | 本次自检通过的镜像身份 | 第 2 步 |
| schemaSha256 | 当前数据库结构摘要 | 第 4 步 |
| backupId | 30 分钟内的新备份编号 | 第 3 步 |
| backupManifestSha256 | 该备份清单的摘要 | 第 3 步 |

按钮禁用时先看这六项和步骤状态。选错 Agent、镜像未自检、备份过期、结构不完整或身份不匹配，都不能登记。曾经登记失败时，先查看只读基线状态，再勾选“我已复核上次失败及只读基线状态”；该勾选只是人工确认，不会修复数据库。

## 会留下什么

- 本地：`D:/idea_work/shiguangxv/target/app.jar`、测试报告和编译输出；平台数据库保存会话、运行、审批与审计。
- 服务器候选：`/root/opt/old-things-releases/<releaseId>/`；构建和基线尝试记录在该候选目录的专属子目录内。
- 服务器备份：`/root/opt/old-things-backups/<backupId>/`，包含敏感材料，全部保留。
- Docker：候选应用镜像、基础镜像及下载缓存。临时构建器/维护容器会按本次身份尝试清理；失败或断线时必须核对清理回执。
- 数据库：第 5 步成功后新增 `old_things.flyway_schema_history` 和版本 1 基线记录。

目前没有自动回收全部产物的功能。旧备份超过时限不等于废弃，旧候选和镜像也必须核对引用后才能清理。已确认无引用的临时构建产物应按准确身份清理；不要用全局 prune。备份校验和材料展开演练属于高级区的可选验证，不在本六步中，当前演练也不等于已在真实数据库完成恢复测试。
