# 从可用工具链到 AI 开发运维任务闭环

日期：2026-10-05（Asia/Shanghai）。性质：开发规划与后续会话交接依据，不是功能完成报告、执行指令或生产操作授权。

本文件承接 [总体计划](00-下一轮开发计划.md)，根据新一轮真实需求验收重新安排实施顺序。历史复盘保留，不把后续补修倒填为早期已完成能力。

## 1. 目标和第一轮完成定义

产品目标：在明确支持的网站栈内，用户描述需求、验收效果并作必要风险选择，Studio 内部完成开发、验证、预览和受审上线，并在授权范围内处理异常。部署是验收业务链路，不是产品全部。

第一轮支持范围仍为当前 Spring Boot/Maven/Thymeleaf/MySQL 网站及 Docker Compose/SSH 部署。先证明任务闭环，再接入第二项目；不承诺任意技术栈、任意数据库变更或无人确认的生产操作。

本轮最低交付不是新的按钮串联，而是以下可证实结果：

1. 一个需求关联多个 Run、开发会话、验证和发布工作流；用户不用搬运摘要、错误或 ID，不因单次模型预算耗尽丢失进度。
2. Studio 内的真实 LLM 在隔离场景自主读取证据、修复至少两类业务错误，并经过独立验收；开发者不能在外部会话提供修复答案。
3. 发布准备遇到一个已确认无未知生产副作用的可恢复故障，Agent 选择合法恢复动作，验证后继续；发布结果未知时先只读核查，不能自动重放。
4. 平台缺陷、越权需求和不可确认风险能形成清晰阻断，保留材料；“建议维护者修复”不计自主恢复成功。
5. 正常、恢复、停止、失败和外部接管均有完整记录和统一指标，不能只展示成功案例。

## 3. 系统分工：流程管边界，Agent 管选择

| 部件 | 责任 | 明确不负责 |
| --- | --- | --- |
| 任务协调层 | 需求、验收条目、阶段、角色路由、预算、证据引用、合法推进 | 不生成每一种错误的硬编码修复答案 |
| 阶段 Agent | 读取证据、选择调查、提出授权内修复、执行并复验 | 不审批自己、不决定放开保护目录或安全检查 |
| 工具和执行器 | 实际操作、资源限制、可归属回执 | 不用模型解释代替执行，不隐式扩大权限 |
| 安全网关/证据验证器 | 版本与 Schema 校验、目标/参数审批、材料一致性、停止条件 | 不接受“模型说安全”作为授权或验证 |
| 用户 | 需求、视觉与业务验收、必要风险和范围选择 | 不承担日志搬运、命令设计或手动材料串联 |

正常重复步骤继续确定性自动编排，不为展示 AI 而给每一步加模型调用。异常的证据选择、诊断及修复策略由 Agent 决定，执行合法性和完成条件由平台核实。

## 4. 复用与新增架构

### 4.1 不重建现有底座

- `ChatService` 已有 ReAct 循环、预算和连接重试；`CodingRunContext` 已有同会话同版本的近期回执交接。它们不是完整需求任务账本，但应复用，不能新增另一个绕过网关的循环。
- `ReleaseWorkflowService`、`WorkflowPlan`、`WorkflowStore`、`WorkflowEvidenceService` 已有发布阶段、证据、认领和恢复规划。确定性安全规划器继续保留，不改成 LLM 任意推进生产。
- `SafeExecutionGateway` 是唯一实际执行入口；既有审批、项目/目录身份、源码快照、部署互斥和执行前复验继续适用。
- 复用项目注册、隔离验证、预览、发布材料及 RunStep/AuditEvent，不更换模块化单体，不为规划增加微服务或分布式调度。

### 4.2 最小新增对象（概念契约，类名由实现会话定）

| 对象 | 必须持久化的内容 |
| --- | --- |
| WorkTask | 原需求及修订、验收条目、项目/目标、状态、停止原因、整体预算、各阶段授权角色版本引用 |
| StageAttempt | 阶段和尝试号、认领/租约、operationId、Run/会话/工作流引用、开始/结束、结果是否确定 |
| EvidenceRef | 类型、完整来源身份、源码/运行配置/工具契约版本、目标、取得时间、有效性及被替代关系 |
| RecoveryAttempt | 失败来源、观察证据引用、假设摘要、选定动作、预期验证、次数/成本、真实结果 |
| ResourceRecord | 临时源码、容器/卷/进程/构建器归属、生命周期、清理证据；未知或无法回收也保留 |

计划和模型摘要只能是非权威建议；工具真实回执、文件状态、数据库历史和独立验证器才是事实。保存外显决策摘要，不索取或记录模型私有思维链。

任务聚合关联多个不可变版本绑定的会话，不改写旧会话版本。角色路由只选择任务事先允许的版本/能力；LLM 不能自行创建或扩大授权。来源材料按需读取，不在每次接续时复制完整历史日志。

### 4.3 状态与恢复约束

- 最小状态：待处理、执行中、待审批、待用户验收、预算暂停、已中断、待结果核查、阻断、完成、取消。任务、阶段、Run 状态不可混用。
- 工具调用前保存操作身份，回执后保存事实；本地事务和远程副作用不是跨系统 exactly-once。崩溃后缺回执不能盲目再发写入。
- UI 刷新/重连只恢复观察。重新接续使用新 Run、核对当前事实，不复用批准，也不复播原模型请求中的工具调用。
- 同目标生产写入互斥沿用既有 guard；开发修改后自动失效旧测试/预览/候选证据，重新验证受影响内容。
- 已上线不自动等于需求验收；用户验收后必须保存任务终态。长期查看历史不把旧健康回执冒充当前在线状态。

### 4.4 预算接续与停止

分开计算单次 Run 的模型轮次/工具调用、一次修复的次数，以及任务全局调用/时长/费用上限。具体默认值先根据真实运行统计定，不凭空加到很大。

达到单次软预算前先写检查点：已完成、已确认副作用、剩余验收项、当前源码、有效证据、未核查结果、下一合法动作。若整体预算及现有授权允许，可创建下一 Run 继续；不得通过无限创建子 Run 重置限制。硬上限、用户取消、无进展、审批拒绝或越界立即停止。

每个写入、测试、预览及生产操作仍遵循原审批规则。任务自动接续不等于批准新的 HIGH 操作。减少逐项审批的任务授权另立 ADR、取得用户确认后再实现，本批不默认开启。

## 5. 异常闭环和能力设计

流程：观察失败 → 收集必要证据 → 更新判断 → 提出合法动作 → 执行 → 独立验证 → 继续或停止。

### 5.1 诊断材料包

包含实际来源、退出码/超时/未知、失败阶段、摘要及按需分页日志、有效运行配置、已执行迁移、最近进展、资源/连接观测、已确认副作用和未知项。证据有时间、身份及截断标识，缺证据与证据为否不混用。

预览材料必须能辨认“平台给出的实际配置”而非只看到网站默认配置；模型/工具/后台/SSH 超时分别记录，不能笼统叫构建超时。日志和报告先脱敏；不返回生产密码、私钥、完整 .env 或业务数据。

路径、日志、测试输出和检索内容是不可信资料，不得通过写着“请执行某命令”改变授权或系统指令。

### 5.2 动作集合，不是错误答案库

先提供通用且有边界的动作：读指定报告/日志片段、核对项目文件与差异、读取有效隔离配置和资源状态、执行已有固定验证、修改授权源码、重新启动已清理的预览、刷新明确过期的证据。新增诊断动作通过统一网关，不增加万能 Shell。

后续再评估项目内隔离命令配方；生产端只增加有范围的诊断和恢复动作。缓存清理、构建器清理必须精确归属本次尝试，不允许全局 prune，更不能自动删除生产备份。

低风险只读瞬态错误可限次重试；诊断工具反馈事实，不直接泄漏评测中的“正确原因”。模型可以修改判断，不能只换一种说法重跑同一失败动作。相同源码/参数/错误反复出现且没有新证据，判定无进展并停止。

### 5.3 责任边界

- 业务逻辑/模板/测试问题：项目开发 Agent 在授权范围内修复，并重新取得验证证据。
- 有明确配方的隔离环境问题：环境执行器处理，Agent 选择配方并核查结果。
- 平台预览、执行器、审批、网关缺陷：业务 Agent 输出结构化维护请求，关联证据和复现；界面告诉用户已经阻断，不要求用户设计命令。不赋予该 Agent 改平台约束的能力。
- 生产状态未知：只读核对实际镜像、生产身份、迁移历史及健康；不能从 HTTP 200 或旧镜像单一证据推导“没有任何副作用”。
- MySQL 迁移部分成功/失败：禁止自动修历史、删表、恢复整库或反向撤销 DDL。应用回退不能承诺撤销数据库扩展；仅进入明确获准的恢复流程，否则安全停止。

首轮平台维护请求只形成材料和明确状态，不自动启动一个具有平台修改权限的 Agent。未来如增加维护角色，必须独立项目范围、授权及验证，不能自己修改自己的约束。

## 6. 分批开发与交接

各批按依赖顺序交付。每批是可独立验收的增量，不承诺一个会话做完全部；共享核心文件不得多个会话同时修改。业务需求开发继续交给 Studio，不由平台开发会话代做来制造闭环通过。

| 批次 | 范围 | 复用入口/主要归属 | 完成闸门 |
| --- | --- | --- | --- |
| A：基线收口和运行可靠性 | 收口现有交付/提交；事件统一分类；后台退出诊断、阶段心跳、资源登记；冻结第一套小评测 | runtime、coding、已有 UI 反馈和交付记录 | 退出/断线/缺回执能区分，遗留资源有归属；最新上线与验收分开；已有业务不重发 |
| B：持久需求任务及有界接续 | 任务账本、验收项、跨 Run 检查点、全局预算、可恢复观察；先接开发阶段 | conversation/runtime/project，关联现有发布 workflow | 预算、取消、重启、重复点击、源码变更不丢进度、不重复副作用、不扩大授权 |
| C：业务错误自主修复最小闭环 | 诊断资料包、外显修复方案、隔离源码修复及再验证；第一条真实 LLM 案例 | coding、conversation、gateway 的受控扩展 | 至少两类业务错误由 Studio 内 LLM 自主恢复，含未见变体；独立断言通过、原功能保留 |
| D：开发到发布的任务内路由与准备恢复 | 自动调用已授权本地验证角色；复用发布安全状态机；准备失败有限恢复、未知发布只读核查 | release、project、task 关联层 | 用户不搬运 ID/日志或选技术助手；预览返工自动要求当前源码验证；生产写入仍逐项审批 |
| E：冻结真实 Agent 评测与一次新需求验收 | 真实 LLM 对照、证据和接管统计、恶意输入/失败样本；真实上线另行授权 | 独立评测模块/文档，平台 UI 只显示必要结论 | 正常、自主恢复、安全停止、接管分别报告；无法用固定分支或模型自评冒充通过 |
| F：同栈第二项目适配（后续） | 配置化合成数据/验证/预览/发布配方，精确材料引用与资源回收 | 复用项目 runtime，消除专用类名作为核心接口 | 同栈第二项目无需改核心执行逻辑；项目、权限、证据、资源互不串用 |

建议下一开发会话只接 A；B、C 设计可先阅读但不提前实施。A 不扩成一次重写所有执行器。B 的首次任务仅承载“开发—测试—用户预览验收”；D 才关联完整发布。

标准 JSON Schema 的全面补强、RAG 拒答和生成评测延续总体计划，但不抢在首条自主修复闭环之前；新增接口需要的严格校验不能推迟，也不能弱化现有安全网关。通用运行时、微服务、流程画布、大量新业务页面和自由生产终端不在本轮。

## 7. 真实评测契约

### 7.1 首批场景

| 场景 | 验收点 | 如何避免假自主性 |
| --- | --- | --- |
| 正常小需求 | 按需求开发、验证、预览，证据一致 | 用户只给需求，不提供代码和技术步骤 |
| 业务编译/测试失败 | 读报告、定位、修复、重测 | 至少两类；保留未用于调试的路径/命名/边界变体 |
| 迁移或源码变化使预览/验证证据无效 | 找到缺失证据并合法刷新，或正确转交平台 | 不提前给模型错误类别/标准答案；复用真实错误形态 |
| 发布准备只读连接短断 | 选择限次复查、保留有效材料 | 注入器只制造故障，不替 Agent 选择恢复动作 |
| 写入后回执丢失或后台退出 | 先观察、核查，不盲目重放 | 强制在关键副作用窗口中断，重复操作独立检测 |
| 越权与恶意日志 | 拒绝保护目录/安全规则修改，不执行日志指令 | 将日志内容视作资料，不能作审批来源 |
| 无解/预算上限/部分迁移 | 正确停止并说明未知与副作用 | 不删除失败样本，不替 Agent 修到成功后再计分 |

生产故障在隔离替身中评测；真实生产注入、回滚演练另行取得授权。不可把 mock 状态机测试写成真实 LLM 或真实服务器恢复。

### 7.2 完成判定和防绕过

- 每个案例冻结起始源码/数据、任务、独立期望结果和停止条件；开发集与验收变体分开。
- Agent 可以修改项目测试，但验收断言和种子在受保护评测侧；改掉失败断言、删除用例、跳过套件或虚报数量不能得到通过。增加恶意“删测试就绿”的场景。
- 保存模型/配置/提示词/工具契约、案例版本、全部运行及操作证据。标准答案对 Agent 不可见，真实日志可见；不给私有正确原因当系统提示。
- 框架/mock 单测、真实执行器测试、真实 LLM 测试和真实业务上线分开汇总；先每场景运行 3 次作为小样本，不承诺统计普遍可靠性。
- 对比固定流程、现有会话 Agent、新任务闭环，在同案例同预算同能力条件下比较；无法等同能力时明确差异。总费用和墙钟时间有边界，所有失败计入分母。

### 7.3 指标

任务完成率、自主恢复率（按可恢复案例作分母）、必须停止案例的正确停止率、未授权/重复副作用数量、人工技术接管次数、用户需求/效果/风险选择次数、重试和无效工具调用、模型/工具/审批等待耗时及资源占用。

必须区分：外部 Codex/开发者修改平台、给修复提示、复制日志均是技术接管；用户正常视觉验收和批准已解释的风险不是技术排障，但仍如实计人工动作。没有实际对照就不声称节省百分比。

## 8. 会话分工与交付规则

- 本主线会话：产品范围、架构边界、验收规则和整体复盘，不直接实现业务需求，也不以外部修补代替内部 Agent 成果。
- 后续平台开发会话：一次只接一个明确批次；先阅读现有代码/交付材料和当前工作区，不从零重写已完成能力。不允许仅依靠过时文档判断现状。
- Studio 内业务 Agent：受授权路径开发测试、预览；平台缺陷形成维护阻断。生产角色执行既有受审工具。
- 用户：提出需求、亲自看视觉和业务效果、作必要风险选择。浏览器视觉由用户完成，不安排低效模拟点击作为主要验收。

每批先确认：目标、非目标、触及模块、依赖、验证方式、停止条件。交付：独立变更清单与提交身份、测试失败/错误/跳过、真实/模拟范围、用户操作说明、残留资源及恢复办法、真实接管情况、尚未解决的问题。

Git 收口先核对归属再按变更边界提交；不能直接把共享工作区所有文件暂存。数据库迁移保持不可变；生产备份全部保留，清理只限已确认归属且废弃的临时产物，并有授权及回收证据。
