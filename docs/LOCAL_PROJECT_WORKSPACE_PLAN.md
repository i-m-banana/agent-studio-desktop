# 本地项目、会话工作区与模型编辑调整方案

状态：已实施并更新本地服务，详见 [交付与检查记录](LOCAL_PROJECT_WORKSPACE_DELIVERY.md)。已按用户授权登记 `D:\idea_work\shiguangxv`；真实数据保护范围仍待确认，项目编码和测试尚未开放。以下保留原设计依据。

## 现状与问题

本次核对了源码；用户报告的“本地代码助手 v2 默认目录不存在”作为验收发现记录，没有据此自动修改本地配置。

- CodingWorkspace 使用全局 `AGENT_STUDIO_CODING_WORKSPACE`，缺省为相对目录 `../coding-workspace`，执行时才检查目录。助手绑定工具不代表已具备可用工作区。
- 会话目前绑定助手版本，没有本地项目和工作区版本绑定。
- 编码工具未覆盖 AgentTool 的默认目标 `LOCAL`。审批已经绑定运行、会话、助手版本和参数摘要，也会复核目标，但本地编码目标没有明确到实际目录。
- 发布构建从 RemoteDeploymentProfile.localSourceRoot 读取源码，与编码根分开配置。不同目录可能是合理的快照构建设计，但目前缺少共同的项目身份和来源校验。
- 路径检查已限制相对路径、越界、链接及部分秘密文件；真实数据库、上传文件、备份等并没有完整的项目保护规则。
- 既有补丁工具只修改已有文本文件，明确不新建、删除或重命名。测试工具虽然限制命令种类，仍会执行项目代码，路径检查不能构成进程隔离。
- 模型更新接口已存在；助手发布版本存有模型配置快照，因此模型编辑需要说明对已发布版本的影响。

## 1. 补上模型编辑

在 01 模型配置的卡片增加“编辑”，复用现有表单和更新接口。编辑状态显示“保存修改 / 取消”，避免误创建新配置。

允许修改名称、服务类型、地址、模型名称、温度和密钥环境变量名；不回显实际密钥。保存后刷新卡片。清楚说明：修改用于后续发布的助手版本；已有发布版本和历史会话保留原快照，不静默迁移。取消不保存，失败保留已填写内容。

## 2. 界面管理本地项目

保留现有八个导航模块，新增独立的 05 项目管理页面；06 对话测试台只显示项目下拉框和状态，管理入口跳转到项目管理。项目配置不再放在助手管理中。

第一期支持登记已有目录、检查、修改配置、归档，不创建业务网站或生成项目模板。用户填写项目名称、明确的源码目录、允许修改的源码/测试子目录、受保护目录，并可关联已有发布目标。登记保存到 MySQL 的只是配置和版本；源码仍在本机原目录。

登记后显示“可用 / 目录不存在 / 配置需处理”和具体原因。目录不存在时禁止文件工具运行，提供“管理本地项目”入口，不自动创建默认目录。归档只停止新会话使用，不删磁盘源码或历史记录。

服务器维护允许登记的具体项目根清单；页面只能登记清单内的项目，不能扩大服务器边界。拒绝盘符根、共享工作父目录（例如整个 D:/idea_work）、系统及用户配置目录；登记一个项目不授权它的兄弟目录。检查解析后的真实路径、重叠的保护目录和 Windows 路径重定向。新增授权目录由用户明确指定并单独确认，模型不能登记或修改项目授权。

## 3. 会话绑定工作区

助手可设置默认项目，但项目选择必须在开始编码前可见。新会话保存项目 ID、配置版本和解析后的工作区身份；运行从服务端会话绑定获取工作区，模型只能传相对文件路径，不能传绝对根目录或任意项目 ID。

会话开始后不通过助手默认项目变化切换目录。换项目时新建会话。项目路径或保护策略改变后，旧会话仍可查看，但暂停新的文件操作，要求明确迁移到新配置并作废待审批；运行中不允许变更该项目配置。其他普通聊天不强制绑定项目。

旧历史会话不自动绑定现有默认目录。继续编码前需要确认所属项目并创建可追溯的新绑定。每个项目串行执行写入和构建任务，防止多个会话相互覆盖文件。

## 4. 审批绑定实际目标

沿用已有浮动审批卡，增加直观信息：项目名称、实际源码根、相对文件、操作类型；修改显示差异，新建显示完整文本，测试显示实际任务和隔离环境。

审批记录绑定项目/配置版本、工作区身份、运行、会话、工具、参数摘要、目标路径以及文件前置条件。已有文件绑定读取时摘要；新文件绑定“不存在”、父目录身份和拟写入内容摘要。执行前再次校验，配置、文件或目录身份变化则拒绝执行并要求重新审批；审批一次性使用，不能跨会话、跨项目重放。

将不可变的执行上下文传到工具，而不是仅依赖全局单例目录或审批中的显示文本。远程发布审批继续绑定远端身份，并追加本地项目及制品来源，不以项目绑定替代原有发布审批。

## 5. 编码与发布共享项目身份

发布配置关联本地项目，从该项目派生源码来源，不再独立维护一个容易漂移的任意源码根。

第一期优先要求编码目录与登记的发布源码目录一致；如果现有发布配置不同，显示“源码来源不一致”，保持只读核查并阻止生成新的发布候选，不自动合并目录或复制源码。

后续若使用独立构建副本，需要明确展示原项目、源目录、提交号或文件清单摘要及构建副本。候选制品绑定本次源快照和测试证据；源码变化后不得把旧结果标为当前验证通过。保留既有不可变候选、远端验证与发布审批流程。

## 6. 真实数据目录保护

由用户登记实际的数据目录：数据库文件、上传文件、业务附件、备份、日志中敏感内容、凭据等；同时保留已有秘密文件保护。使用解析后的路径和目录身份判断，不能只靠文件夹名。保护规则优先于允许修改目录，覆盖列目录、搜索、读取、写入、新建以及相关发布收集路径；被保护区域不进入模型上下文。

所有能访问本地文件的内置工具都要排查，包括笔记工具、发布构建和文件收集。外部 MCP 若具有独立文件/命令权限，不能假设服从本地项目规则；受保护编码模式中禁用未验证的此类工具，或通过同一执行边界接入。

特别限制：测试、npm 脚本、Maven 插件及构建代码可以访问目录外的文件或网络，审批和固定命令本身不能阻止。安全验证应在专用低权限隔离环境的源码副本中运行，只开放源码与临时输出，隔离真实数据、主机凭据和生产网络；测试使用专用数据。容器挂载、运行身份、网络和凭据都需要检查，不能仅用“在容器里”作为安全依据。在隔离尚未完成时，不对含真实数据访问权限的项目承诺安全测试，保持验证功能关闭并说明原因。发布本地构建执行同样需要纳入此边界。

## 7. 安全新建源码/测试文件的评估

结论：可以新增独立的受审批文本创建工具，前提是项目绑定与保护规则先落地。不要扩展现有精确补丁工具为可任意创建或覆盖。

- 只允许用户配置的源码/测试子目录和文件类型；默认不允许创建脚本、构建配置、部署配置、密钥或二进制文件。
- 第一版只在已有父目录创建单个 UTF-8 文件；不隐式创建目录、不解压、不覆盖、不删文件、不执行创建的内容。文本有明确大小上限。
- 审批展示目标和完整内容；再次核对父路径、符号链接、Windows junction/reparse point、硬链接风险、大小写别名、设备名和数据流语法。
- 使用不会覆盖已有目标的创建语义；并发出现同名文件立即失败。处理路径检查与实际创建之间的竞态，在支持的平台使用稳定目录句柄等措施；无法保证边界的文件系统上关闭写入，不能用一次字符串检查替代。
- 创建成功记录内容摘要、项目、审批和结果；发生错误不得留下被当成成功的半文件。先在临时测试项目验证，绝不拿真实数据目录试写。

允许创建测试文件不等于允许运行测试。新建能力和执行能力分别授权、分别审批。

## 实施顺序与验收

| 顺序 | 交付 | 验收现象 |
|---|---|---|
| A | 模型编辑、本地项目登记与目录检查 | 能编辑模型；无效目录清楚提示；D:/ 和共享父目录不能登记为工作区；不自动新建目录 |

| D | 受审批源码/测试文件创建 | 审批前无写入；只创建允许文件；同名、越界、链接和竞态失败；审计能追溯 |

近期先完成 A、B；C 是安全运行的必需条件；D 的上线依赖项目绑定、保护与写入边界验证。每批单独交付，不同时扩展业务网站能力。所有操作在测试项目和假数据中验收，原有会话、源码、真实数据库及发布配置不自动迁移。
