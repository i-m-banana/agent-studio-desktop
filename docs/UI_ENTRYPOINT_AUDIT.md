# UI入口与接口核查

核查日期：2026-10-02。用户已验收本轮改造。本次只做代码对照，没有补功能或删除接口。

## 结论

核对15个业务Controller的63条HTTP路由、前端调用与事件绑定，并对照改造前的 `fb651e8`。

- 未发现这几轮改造把原来可用的页面功能改成无入口接口。
- 确认1条业务接口没有UI入口：修改已有模型配置。它在改造前已经如此。
- 1条状态接口没有页面按钮，但启动脚本仍在调用，不能算孤立接口。
- 审批迁移留下3项不再使用的前端参数；属于代码冗余，不是后端接口，也没有导致审批功能丢失。

## 确认没有UI入口的业务接口

`PUT /api/models/{id}`：更新已有模型的显示名称、地址、模型名、凭据名称和温度。

后端位置：`backend/src/main/java/com/agentstudio/model/ModelProfileController.java:37`，由ModelProfileService.update实现。

前端01页现有表单只调用 `POST /api/models` 新建配置，已配置模型卡片没有编辑按钮。安全凭据的更新入口仍存在，但修改密钥不等于修改模型连接配置。

对照 `git show fb651e8:web/src/App.tsx`，改造前也只有模型列表读取与创建调用，没有模型更新调用。原全盘UI审查已把它记录为M01。此次用户收敛3B范围后，没有新增模型编辑，因此这个旧缺口仍然保留。

## 没有页面按钮但有实际调用的接口

`GET /api/system/status`：由 `scripts/start.ps1:42` 读取，用于确认本地后端已启动和版本正确。页面诊断调用 `GET /api/system/readiness`。两个接口用途不同。

框架健康接口 `/actuator/health`、`/actuator/info` 是维护接口，未计入上述63条业务路由，也不需要为每条维护接口增加页面按钮。

## 前端冗余参数

RemoteWorkbench仍声明并接收 `approvalSecondsLeft`、`approvalBusy`、`onDecideApproval`，但迁移审批卡后不再读取这三项。有效的倒计时、提交状态与审批回调现在由全局RunDock使用。

这三项可在代码整理时移除；当前检查没有改动已验收的运行代码。`pendingApproval`仍被远程工作台的布局提醒使用，不能一起直接删除。

本结论基于当前源代码、路由、页面事件绑定和改造前版本的对照，不声称重新执行了所有真实模型、SSH、发布与审批操作。
